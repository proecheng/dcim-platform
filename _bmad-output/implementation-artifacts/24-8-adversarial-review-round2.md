## 审查发现（12 个问题）

### 🔴 高严重度问题（必须修复）

1. **系统内通知表未定义** - AC #2 说"写入系统内通知表"，但整个 Story 没有定义这个表的结构。
   - **修复方案**: 明确复用现有 `system_notifications` 表（如果存在），或定义新表结构

2. **分级展示中 conclusion 字段来源不明** - AC #3 说 viewer 可以看到 `conclusion`，但 `diagnosis_sessions` 表没有这个字段。
   - **修复方案**: 明确 conclusion 来自 `diagnosis_results` 表，需要关联查询

3. **标注删除是物理删除还是软删除** - AC 和安全考虑中说法不一致。
   - **修复方案**: 明确使用物理删除（简化实现），在安全考虑中说明审计通过标注历史记录实现

4. **偏差检测任务的并发安全问题** - 多实例部署时可能重复执行。
   - **修复方案**: 使用 Redis 分布式锁确保只有一个实例执行

### 🟡 中严重度问题（建议修复）

5. **P95 百分位数计算不明确** - 边界情况处理不清晰。
   - **修复方案**: 明确计算方法：对所有用户的标注率排序，取第 95 百分位值

6. **ORM 模型关系未定义** - 影响查询性能。
   - **修复方案**: 明确使用 `relationship()` 和 lazy 加载策略

7. **标注统计 API 缺少分页** - 可能返回过大响应。
   - **修复方案**: 添加分页参数和 top_n 限制

8. **偏差检测的"偏差倍数"计算不明确** - 告警内容不清晰。
   - **修复方案**: 明确计算公式：`(user_rate - threshold) / threshold`

9. **标注列表 API 的自动过滤逻辑不安全** - 可能导致混淆。
   - **修复方案**: operator 传入其他用户 ID 时返回 403，而非静默过滤

### 🟢 低严重度问题（可选修复）

10. **前端 confidence_level 映射逻辑缺失** - 实施细节不明确。
    - **修复方案**: 明确在后端映射，从 diagnosis_results 表获取 confidence

11. **idx_annotations_type 索引可能无用** - 过度索引。
    - **修复方案**: 移除单独的 type 索引，改为复合索引 `(session_id, annotation)`

12. **前端 userRole 来源不明** - 实施细节缺失。
    - **修复方案**: 明确从 Pinia user store 获取
