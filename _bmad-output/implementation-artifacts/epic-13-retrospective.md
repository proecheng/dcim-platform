## 关键经验教训

### 安全与合规基线

1. **等保二级要求驱动设计** — 13-2 并发会话限制（最多 3 个，超限踢出最早会话）和 13-6 密码策略（至少 3 类字符、历史密码检查、90 天过期提醒）均源自等保二级要求。UserSession 模型通过 token_jti 追踪活跃会话，JWT 验证失败时写入安全告警日志。

2. **密码策略可配置化** — 13-6 将策略参数（最小长度、复杂度要求、历史次数、过期天数）存储在 SystemConfig 表中，避免硬编码。PasswordHistory 模型记录最近 5 次密码哈希用于重复检测。

3. **站点级数据隔离** — 13-5 通过 UserSite 多对多关联表实现用户-站点权限绑定，admin 角色自动拥有所有站点访问权限。依赖注入函数 get_user_site_ids 统一处理过滤逻辑，避免各 API 重复实现。

### 技术模式沉淀

- **会话管理**：登录创建 UserSession，超过 3 个踢出最早会话，被踢用户返回 401 + 明确提示
- **站点过滤依赖注入**：admin 返回 None（不过滤），operator/viewer 返回关联站点 ID 列表
- **用户管理前端**：Element Plus Table + Pagination + Dialog，支持搜索/筛选/批量删除
- **密码复杂度**：从要求全部 4 类字符放宽为至少 3 类，平衡安全性和用户体验

### 注意事项

- Device 表新增 site_id 为可选字段（nullable），兼容已有数据，但新设备应强制关联站点
- 并发会话限制在多标签页场景下可能导致用户体验问题，需在前端提示
