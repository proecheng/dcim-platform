## 关键经验教训

### 对抗性审查高价值发现

- **7-5 C-03/C-04**: 除零风险（required_u=0）→ 用 `Field(..., ge=1)` 和显式零检查防护
- **7-5 H-01**: 二元评分（100 or 0）导致零区分度 → 改为渐进式评分 `min(100, (value/required)*50)`
- **7-6 C1**: SQLite 无 ISO 周号支持 → Python 层 `isocalendar()` 分组替代
- **7-6 C3**: Simulator 事务隔离 → 容量快照必须独立 session，失败不影响主循环
- **7-6 H-3**: 置信区间基于未 clamp 的预测值 → 边界处语义错误

### 代码审查高价值发现

- **7-5 H-1**: 混合手动/ORM 响应构造 → 简化为 `db.refresh(plan)` + `model_validate`
- **7-5 M-2**: `startswith` 前缀匹配边界 → 添加 `/` 分隔符检查
- **7-6 H-4**: Demo 路径缺少增长超阈值的扩容建议 → 补充 `first_exceed_idx` 逻辑
- **7-6 H-6**: 全表加载到内存做 Python 聚合 → 改用 SQL `func.sum()` + `func.coalesce()`

### 技术模式沉淀

1. **路由顺序**: FastAPI 中静态路由（/trend, /forecast）必须在参数化路由（/{id}）之前
2. **ORM session 安全**: `expire_on_commit=False` 全局设置；后台任务用独立 session
3. **前端 API 对齐**: 前端已有 API 函数时，后端必须精确匹配其请求/响应签名
4. **Location 前缀匹配**: 必须加 `/` 边界检查，避免 "Room1" 匹配 "Room10"
5. **`value or fallback`**: 对 0.0 会误判为 falsy，必须用 `if value is not None`
