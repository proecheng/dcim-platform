## 关键经验教训

### 数据聚合层设计

1. **报表数据来源分散** — 12-1 自动报表需要聚合告警趋势、能耗对比、工单统计、设备可用率等多模块数据。ReportRecord 新增 report_data 字段存储完整 JSON 快照，避免回溯查询时数据已变化。

2. **智能摘要面板跨模块聚合** — 12-2 需要从告警、工单审批、巡检、资产维保、容量等 6 个数据源聚合待处理事项。统一的 SummaryItem 结构（type/title/priority/count/action/link）简化了前端渲染逻辑。

3. **PDF 生成复用已有基础** — 12-3 基于已有的 reportlab PDF 生成器（services/pdf_generator.py）和中文字体支持，新增 generate_auto_report_pdf 函数读取 report_data JSON 生成多维度 PDF。

### 技术模式沉淀

- **报表调度配置**：ReportTemplate 支持 daily/weekly/monthly/custom 四种频率，auto-generate API 按周期类型触发
- **健康度评分算法**：基础分 100，紧急告警 -15、重要告警 -8、次要告警 -3、维保逾期 -20、近期维保 +5，clamp 到 0-100
- **健康等级划分**：80-100 健康、60-79 关注、40-59 预警、0-39 危险
- **同比环比分析**：嵌入报表数据，复用 statistics API 的 comparison 端点

### 注意事项

- PDF 生成为同步操作，大量数据时可能阻塞请求，生产环境建议异步生成
- 设备健康度评估依赖告警和维保数据的完整性，新接入设备初期评分可能偏高
