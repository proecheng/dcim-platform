# Story 24.8 对抗性审查 - 第一轮

**审查日期**: 2026-03-06
**审查者**: Claude Opus 4.6
**Story**: 24-8-diagnosis-result-annotation-and-rbac

## 审查发现（15 个问题）

### 🔴 高严重度问题（必须修复）

1. **外键约束不一致** - `annotator_id` 使用 `ON DELETE SET NULL`，但字段定义为 `NOT NULL`，这是矛盾的。当用户被删除时，数据库会尝试将 `annotator_id` 设为 NULL，但 NOT NULL 约束会阻止这个操作，导致删除用户失败。
   - **修复方案**: 移除 `NOT NULL` 约束，允许 `annotator_id` 为 NULL（表示标注者已被删除）

2. **标注列表 API 缺少权限控制** - `GET /api/v1/diagnosis/annotations` 没有明确的权限要求，存在安全漏洞。
   - **修复方案**: 明确权限规则：operator+ 可查看自己的标注，admin 可查看所有标注

3. **actual_root_cause 长度限制不一致** - Dev Notes 说"最大 1000 字符"，但数据库表定义使用 `TEXT` 类型（无长度限制）。
   - **修复方案**: 在数据库层面添加 `CHECK (length(actual_root_cause) <= 1000)` 约束

4. **分级展示字段名不一致** - AC #3 说 admin 可以看到 `audit_log`，但审计日志是单独的表 `diagnosis_audit_log`，不是 session 的字段。
   - **修复方案**: 明确 API 响应结构，audit_log 应该是关联查询的嵌套对象

### 🟡 中严重度问题（建议修复）

5. **缺少标注修改功能** - AC 说"同一用户修改标注"会创建新记录，但没有提供修改标注的 API 端点。
   - **修复方案**: 明确说明修改标注通过再次调用 POST 创建新记录，或添加 PATCH 端点更新最新标注

6. **偏差检测算法有缺陷** - 使用 μ + 2σ 假设正态分布，但标注率是有界的（0-1），可能严重偏斜。
   - **修复方案**: 添加备选方案：当样本量 < 100 时使用绝对阈值（如 > 30%），样本量 ≥ 100 时使用 P95 百分位数

7. **缺少标注删除功能** - 如果用户误标注，无法删除，会污染数据集。
   - **修复方案**: 添加 `DELETE /api/v1/diagnosis/annotations/{id}` 端点（仅允许删除自己的标注，admin 可删除任何标注）

8. **WebSocket 推送失败处理不完整** - 如果管理员不在线，告警会丢失。
   - **修复方案**: 添加持久化告警队列或系统内通知，确保管理员登录后能看到历史告警

9. **偏差检测定时任务缺少错误处理** - 如果任务抛出异常，会静默失败。
   - **修复方案**: 添加 try-except 包裹整个任务，记录错误日志，确保任务失败不影响后续执行

10. **并发标注竞态条件** - 两个用户同时标注同一会话可能创建重复记录。
    - **修复方案**: 添加唯一索引 `UNIQUE(session_id, annotator_id, annotated_at)`（精确到秒），或使用乐观锁

### 🟢 低严重度问题（可选修复）

11. **分级展示逻辑效率低下** - 使用 if-elif-else 过滤字段，需要先加载完整对象。
    - **修复方案**: 使用 SQLAlchemy 的 `load_only()` 在查询层面只选择需要的字段

12. **前端代码缺少加载状态** - 标注对话框没有 loading 状态，用户可能重复点击。
    - **修复方案**: 添加 `submitLoading` 状态，提交时禁用按钮

13. **confidence_level 映射边界值不明确** - 0.8 和 0.6 的边界值属于哪个等级？
    - **修复方案**: 明确为 `[0.8, 1.0]→high, [0.6, 0.8)→medium, [0, 0.6)→low`

14. **缺少标注统计 API** - 管理员需要查看标注统计（总数、占比、用户参与度）。
    - **修复方案**: 添加 `GET /api/v1/diagnosis/annotations/stats` 端点

15. **测试覆盖率不足** - 集成测试没有覆盖偏差检测的边缘情况（标注数刚好 30、所有用户标注率相同、只有一个用户）。
    - **修复方案**: 在 Task 9 中添加边缘情况测试用例
