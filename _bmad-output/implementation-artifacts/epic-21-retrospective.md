# Epic 21 回顾：网关管理前端

## 完成情况

全部 2 个 Story 完成。本 Epic 为网关管理模块实现了完整的列表监控和远程配置下发功能，替换 PlaceholderView 占位组件。

| Story | 标题 | 核心特性 | 前端构建 |
|-------|------|---------|---------|
| 21-1 | 网关列表与状态监控 | 统计卡片 + 表格 + 展开详情 + WebSocket 实时更新 | ✅ |
| 21-2 | 网关远程配置下发 | 配置对话框子组件 + 批量下发 + 历史记录 | ✅ |

**优先级：** P0（最高）

## 关键经验教训

### 新建前端 API 模块

- 这是 Phase 2 补充 Epic 中唯一需要新建前端 API 模块（`frontend/src/api/modules/gateway.ts`）的 Epic。
- Epic 18-20 都复用已有 API 模块，Epic 21 需要封装网关专属接口：列表、汇总、详情、事件历史、配置下发、配置历史。
- 类型定义（`GatewayInfo`、`ConfigPushResponse`、`ConfigPushRecord` 等）也在此模块中新建。

### 对抗性审查修正数据映射

- 21.1 审查发现后端 Gateway 模型缺少多个前端期望的字段：
  - 数据吞吐量 → 用 `datasource_count`（关联数据源数）替代
  - 协议类型 → 用 `capabilities` JSON 字段展示能力标签
  - 连接质量 → 用 `cpu_usage` / `memory_usage` 替代
  - 告警数 → 前端计算（离线数或有 resource_warning 事件的网关数）
- 这是需求与后端模型不完全匹配时的务实处理方式。

### 子组件拆分模式

- 21.2 将配置下发对话框拆为独立的 `GatewayConfigDialog.vue` 子组件，通过 props/emits 与父组件通信。
- 这是 Phase 2 Epic 中首次出现的组件拆分（之前都是单文件页面）。
- 拆分原因：配置下发逻辑（双标签页、批量下发进度、历史记录分页）复杂度足以独立为子组件。

### API 契约审查

- 21.2 审查发现后端 `push-config` 端点不接受请求体参数，仅触发配置构建和下发。
- 前端从"修改配置表单"改为"展示当前配置 + 一键下发"，避免了前后端契约不匹配。
- 批量下发需串行或限制并发，避免 MQTT 拥塞。离线网关返回 503 需优雅处理。
