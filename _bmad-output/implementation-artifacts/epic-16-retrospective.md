## 关键经验教训

### 数据隔离架构

- **行级 site_id 隔离**：所有业务表通过 site_id 字段实现数据隔离，FastAPI 中间件自动注入查询过滤，避免了每个 API 手动添加过滤条件。
- **EMQX ACL 隔离**：MQTT Topic 按 site_id 隔离权限（`dcim/{site_id}/...`），确保不同站点网关数据不会交叉。
- **Epic 13 基础复用**：Story 13-5 已实现站点级数据隔离的基础能力，本 Epic 在此基础上扩展了完整的多站点管理 UI 和网关接入。

### 前端统一视图

- **站点切换**：顶部导航栏站点选择器切换后，所有页面数据联动更新，需要确保 Pinia store 中的 site_id 状态全局一致。
- **"全部站点"视图**：汇总视图的聚合查询需要注意性能，跨站点报表和对比分析依赖后端聚合 API。

### 网关接入扩展

- **断点续传复用**：Epic 2 的离线缓存和断点续传机制在多站点场景下无需修改即可复用，网关本地 SQLite 缓存策略保持一致。
- **200 台设备扩展**：从单站点平滑扩展到多站点 200 台设备，主要瓶颈在数据库查询和 WebSocket 广播，通过 Redis 缓存和分站点推送缓解。
