全部 2 个 Story 完成。本 Epic 为安防消防模块实现了门禁管理和消防联动可视化两个独立页面，替换 PlaceholderView 占位组件。

## 关键经验教训

### 布局模式突破

- Epic 18 的三个页面均为"统计卡片+区域分组卡片+数据表格"模式，Epic 19 引入了两种新布局：
  - **19.1 左右分栏**：左侧 320px 设备列表面板 + 右侧时间线视图，设备切换联动
  - **19.2 三段式**：统计卡片 + 策略配置区（可展开卡片+动作链流程图）+ 执行历史区（表格+可展开时间线）
- 安防模块的交互形态比环境监控更多样化，不能套用单一模板。

### 纯 CSS 动作链流程图

- 19.2 的联动动作链可视化采用纯 CSS/HTML 实现（flex 布局 + 伪元素箭头连线），不依赖第三方图表库。
- 技术决策合理：当前为线性流程，CSS 完全胜任；避免为单个页面引入 D3/mermaid 等重依赖。
- 局限性：如果未来需要分支逻辑或更复杂的流程图，需重新评估方案。

### 事件类型推导逻辑

- 19.1 门禁事件类型不是直接字段，而是从 `alarm_type` + `alarm_level` 组合推导：
  - `threshold` + `info` → 刷卡开门
  - `system` → 远程开门
  - `threshold` + `major/critical` → 异常开门
  - 关联消防联动策略 → 消防联动开门
- 这是隐式映射关系，后端告警分类规则变更可能导致前端推导失败。建议在代码中添加注释说明映射关系。

### 跨模块数据关联深度

- 19.2 消防联动页面涉及四层数据关联：策略 → 执行记录 → 执行日志 → 恢复记录
- Composable `useFireLinkageData.ts` 复杂度明显高于 Epic 18 的 composable，需要管理多个异步数据源和分页状态。

### 纯前端 Epic 延续

- 与 Epic 18 一致，无后端改动，所有 API 端点已就绪。
- 前端构建通过作为主要验证手段。
