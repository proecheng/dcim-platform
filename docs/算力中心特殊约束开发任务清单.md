## Quick Start（快速启动）

1. 切换分支并确认：
   ```bash
   git branch --show-current
   ```
   期望输出：`feature/datacenter-constraints`
2. 启动服务前先清理端口（按仓库规范）：
   ```bash
   netstat -ano | findstr ":8080" | findstr "LISTENING"
   netstat -ano | findstr ":3000" | findstr "LISTENING"
   ```
3. 推荐先执行：
   ```bash
   stop.bat
   start.bat
   ```
4. 若只开发前端（热更新）：
   ```bash
   cd frontend
   npm run dev
   ```
5. 若走 `start.bat` 模式，前端改动后必须重建：
   ```bash
   cd frontend
   npm run build
   ```

- T1（字段兼容与类型定义）是后续后端/前端任务的前置依赖。

## Phase 2（后端约束引擎与 API，2-4 天）

### [ ] T4（P0）实现 IT 负载占比约束校验逻辑
- **任务描述**：
  - 在 `ConstraintChecker` 实现 IT 占比边界校验。
  - 按公式计算最大可转移功率：
    `最大可转移功率 = 总功率 × (制冷占比 × 0.4 + 其他占比 × 0.6)`
  - 输出 violation/warning（含当前值、阈值、建议值）。
- **涉及文件**：
  - `backend/app/services/load_shift/algorithms/constraint_checker.py`
  - （如需）`backend/app/services/load_shift/*.py`（负载分布查询支持）
- **预估工时**：1-1.5 天
- **验收标准**：
  - [ ] 不再出现 IT 相关 TODO 占位 warning。
  - [ ] 边界场景（59.9%/60%/80%/80.1%）行为符合预期。
  - [ ] 返回结构包含可前端直用的详情字段。

### [ ] T5（P0）实现 UPS 容量约束校验逻辑
- **任务描述**：
  - 实现公式：`转移后峰值 ≤ UPS额定容量 × safety_factor`。
  - 支持 `auto_adjust`、`reject_on_exceed` 两类策略。
  - 超限时输出 `suggested_max_shift_power`。
- **涉及文件**：
  - `backend/app/services/load_shift/algorithms/constraint_checker.py`
  - （如需）`backend/app/services/load_shift/*.py`（UPS 容量/当前负载查询）
- **预估工时**：1-1.5 天
- **验收标准**：
  - [ ] 不再出现 UPS 相关 TODO 占位 warning。
  - [ ] `post_peak == max_allowed` 通过，`post_peak > max_allowed` 拒绝或告警。
  - [ ] 返回建议功率用于前端一键应用。

### [ ] T6（P0）约束分析与预检 API 增强
- **任务描述**：
  - 增强 `POST /api/v1/shift/analysis/constraints` 返回细节。
  - 增加（或补齐）preview 接口供前端实时预检。
  - 保证约束 CRUD 支持新类型并做参数范围校验。
- **涉及文件**：
  - `backend/app/api/v1/shift.py`
  - `backend/app/schemas/load_shift.py`
- **预估工时**：0.5-1 天
- **验收标准**：
  - [ ] 响应中包含 `constraint_details.datacenter_load` 与 `constraint_details.ups_capacity`。
  - [ ] 超限时返回 violation + 建议值。
  - [ ] OpenAPI 文档可见新字段结构且示例可读。

## 开发顺序建议（可直接照此执行）

1. **先做 Phase 1（T1/T2）**：先消除字段与类型不一致风险，避免后续返工。  
2. **再做 Phase 2（T4/T5/T6）**：先完成硬约束校验，再开放预检 API。  
3. **最后做 Phase 3（T7/T8/T9）**：前端依赖后端返回结构，测试放在闭环完成后统一收敛。
