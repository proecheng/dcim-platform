# 监测设备接口规范 — 华为动环监测标准

> **文档版本**: V1.0  
> **生成日期**: 2026-02-15  
> **来源**: 基于 kimi-prd.md V4.0 PRD 第5章及华为《动环监测信息内容说明表》整理  
> **适用范围**: 算力中心智能监控系统 (DCIM) 全部监测设备接入

---

## 概述

本文档定义了算力中心智能监控系统中所有监测设备与系统之间的接口协议、数据格式和接入方式。规范参照华为《动环监测信息内容说明表》，覆盖供配电（第一域）、制冷（第二域）、环境（第三域）、安防消防（第四域）、智能基础设施（第五域）五大监测域，是系统协议适配器开发和设备接入的权威参考。

所有监测参数最终统一映射为系统 Point 点位模型（AI/DI/AO/DO 四种类型），通过协议适配器层实现设备原生协议到 Point 数据的转换。当前 V4.0 阶段使用数据模拟器替代真实协议适配器。

## 8. 协议适配器设计要求

- **FR-22.1**: 系统提供协议适配器抽象层，支持 Modbus TCP、Modbus RTU、SNMP、干接点、TCP/IP 私有协议的统一接入
- **FR-22.2**: 每种协议适配器将设备原始数据转换为 Point 点位数据（point_code、value、quality、timestamp）
- **FR-22.3**: 协议适配器支持配置化管理：设备地址、寄存器映射、采集周期、数据转换规则可通过系统配置界面管理
- **FR-22.4**: 当前阶段（V4.0）使用数据模拟器替代真实协议适配器，模拟器按照上述寄存器映射生成合理的模拟数据
- **FR-22.5**: 协议适配器接口预留，后续可逐步替换模拟器为真实设备驱动，无需修改上层业务逻辑

## 9. 开发者指南

本节为开发者提供将本规范中的监测参数接入系统的实践指导。

### 9.1 监测参数到 Point 模型的映射

系统中每一个监测参数对应一个 `Point` 记录（定义于 `backend/app/models/point.py`）。核心字段映射关系：

| 规范字段 | Point 模型字段 | 说明 |
|---------|--------------|------|
| 监测参数 | `point_name` | 点位中文名称 |
| 寄存器地址 | `register_address` | Modbus 寄存器地址，如 `"40001"` |
| 数据类型 | `data_type` | 映射为 `float`/`int`/`bool`/`string` |
| 单位 | `unit` | 工程单位，如 `"℃"`、`"V"`、`"%RH"` |
| Point类型 | `point_type` | `AI`/`DI`/`AO`/`DO` |
| 采集周期 | `collect_interval` | 秒，参照协议总览表中的采集周期 |
| 数据转换 | `scale_factor` + `offset` | 原始值 × scale_factor + offset = 工程值 |
| Modbus功能码 | `function_code` | 如 03(保持寄存器)、02(离散输入) |

### 9.2 point_code 命名规范

系统采用统一的点位编码规则：

```
{区域代码}_{设备类型}_{点位类型}_{序号}
```

各段含义：

| 段 | 取值范围 | 示例 |
|----|---------|------|
| 区域代码 | `A1`, `A2`, `B1`, `B2` 等 | `A1` |
| 设备类型 | `UPS`, `PDU`, `AC`, `TH`, `DOOR`, `SMOKE`, `WATER`, `IR`, `FAN`, `LIGHT`, `BMS`, `FIRE`, `EPO` | `UPS` |
| 点位类型 | `AI`, `DI`, `AO`, `DO` | `AI` |
| 序号 | 三位数字，从 `001` 开始 | `003` |

示例：
- `A1_UPS_AI_001` — A1区 UPS 输入电压
- `A1_UPS_DI_001` — A1区 UPS 市电状态
- `A1_AC_AO_001` — A1区精密空调设定温度
- `A1_DOOR_DI_001` — A1区主入口门禁状态

### 9.3 Point 类型说明

| 类型 | 全称 | 用途 | 数据方向 | 典型场景 |
|------|------|------|---------|---------|
| AI | Analog Input | 模拟量输入 | 设备→系统 | 电压、电流、温度、湿度、功率、频率等连续量 |
| DI | Digital Input | 开关量输入 | 设备→系统 | 运行状态、故障状态、门禁状态、漏水/烟雾告警等 |
| AO | Analog Output | 模拟量输出 | 系统→设备 | 空调设定温度、风机转速设定等 |
| DO | Digital Output | 开关量输出 | 系统→设备 | 空调启停、照明控制、远程开门、紧急断电等 |

映射原则：
- 本规范中标注 `AI` 的参数：连续数值型监测量，只读
- 本规范中标注 `DI` 的参数：状态/枚举/布尔型监测量，只读
- 控制类参数（如远程开门、空调设定温度）使用 `AO`/`DO`
- 枚举型 DI 参数（如压缩机状态 0-4）在 `data_type` 中设为 `int`，通过 `value_text` 展示状态文本

### 9.4 数据模拟器工作方式

当前系统使用数据模拟器（`backend/app/tools/realtime_simulator.py`）为所有点位生成模拟数据，其工作逻辑：

1. **AI 点位**：在 `min_range` ~ `max_range` 范围内生成随机波动值
   - 温度类：基准值 ± 小幅波动（如 24 ± 2℃）
   - 电压/电流类：在额定值附近 ±2% 波动
   - 负载率/功率类：跟随时间曲线（白天高、夜间低）
2. **DI 点位**：大部分时间保持正常状态（0），有 0.5% 概率触发告警状态（1）
3. **AO/DO 点位**：保持上次设定值，或在合理范围内缓慢变化

模拟器每 10 秒更新一次所有启用点位的实时值，写入 `point_realtime` 表。

### 9.5 新增设备类型的开发步骤

当需要接入本规范中定义的新设备类型时，按以下步骤操作：

1. **定义点位**：参照本规范对应章节的寄存器映射表，为每个监测参数创建 Point 记录
   - 在 `init_points.py` 或通过 API 创建点位
   - 按命名规范设置 `point_code`
   - 设置正确的 `point_type`、`unit`、`min_range`、`max_range`、`collect_interval`
   - 填写 `register_address`、`function_code`、`scale_factor` 等通信配置

2. **配置模拟数据**：在模拟器中添加对应设备类型的数据生成逻辑
   - 参照 `realtime_simulator.py` 中已有的模式
   - AI 点位：根据物理含义设置合理的波动范围
   - DI 点位：设置合理的状态切换概率

3. **配置告警阈值**：为关键监测参数设置告警阈值
   - 参照 `init_points.py` 中 `DEFAULT_THRESHOLDS` 的模式
   - 根据设备规范设置合理的告警上下限

4. **前端展示**：在对应的监控面板中添加新设备的数据展示组件

5. **协议适配器（未来）**：当对接真实设备时，实现对应协议的 Adapter
   - 遵循 FR-22.1 ~ FR-22.5 的设计要求
   - Adapter 输出标准 Point 数据（point_code、value、quality、timestamp）
   - 替换模拟器，上层业务逻辑无需修改
