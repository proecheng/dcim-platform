# 遗留系统分析 — V4.0 原系统保留清单

> 基于 kimi-prd.md V4.0 PRD 第3章整理

## 概述

本文档梳理了 DCIM（算力中心智能监控系统）在 V4.0 升级过程中对现有系统的保留策略。V4.0 采用"棕地开发"模式——在已有系统基础上渐进式增强，而非推倒重来。第3章"原系统保留清单"明确了哪些功能模块、页面、状态管理和技术架构在 V4.0 中完整保留，哪些在保留基础上做定向增强。

本文档的目标是为开发团队提供一份独立的参考手册，帮助理解 V4.0 的保留与增强边界，避免在开发过程中对已有功能做破坏性变更。

**保留原则**: 以下功能模块和界面在 V4.0 中完整保留，不做破坏性变更。仅在必要时做增强（标注"增强"）。

---

## 1. 保留的前端页面

V4.0 对前端页面的处理分为三类：**保留不变**（功能和路由均不变）、**保留增强**（功能扩展但保持向后兼容）、**保留迁移**（功能不变但路由归属调整以适配新导航结构）。

| 原路由 | 页面 | V4.0 处理 | 处理类型 |
|--------|------|-----------|----------|
| /dashboard | 监控仪表盘 | 保留，增强为动环综合仪表盘（增加制冷/UPS/安防概览卡片） | 增强 |
| /devices | 点位管理 | 保留不变 | 不变 |
| /device-manage | 设备管理 | 保留，扩展设备类型（新增UPS/空调/传感器/门禁等） | 增强 |
| /alarms | 告警管理 | 保留，增强告警类型（新增安防/消防/环境类告警） | 增强 |
| /history | 历史数据 | 保留不变 | 不变 |
| /reports | 报表分析 | 保留，扩展新模块报表 | 增强 |
| /settings | 系统设置 | 保留不变 | 不变 |
| /energy/monitor | 用电监控 | 保留，移至"供配电管理"下 | 迁移 |
| /energy/statistics | 能耗统计 | 保留，移至"供配电管理"下 | 迁移 |
| /energy/analysis | 节能分析 | 保留，移至"节能中心"一级入口 | 迁移 |
| /energy/config | 配电配置 | 保留，移至"供配电管理"下 | 迁移 |
| /energy/topology | 配电拓扑 | 保留，移至"供配电管理"下 | 迁移 |
| /energy/regulation | 负荷调节 | 保留，移至"节能中心"下 | 迁移 |
| /energy/execution | 执行管理 | 保留，移至"节能中心"下 | 迁移 |
| /asset/list | 资产台账 | 保留，移至"基础设施"下 | 迁移 |
| /asset/cabinet | 机柜管理 | 保留，增强 U 位实时管理 | 增强 |
| /capacity | 容量管理 | 保留，移至"基础设施"下 | 迁移 |
| /operation/workorder | 工单管理 | 保留不变 | 不变 |
| /operation/inspection | 巡检管理 | 保留不变 | 不变 |
| /operation/knowledge | 知识库 | 保留不变 | 不变 |
| /vpp/analysis | VPP 分析 | 保留不变 | 不变 |
| /bigscreen | 数字孪生大屏 | 保留现状（后续由独立数字孪生系统替代） | 不变 |
| /login | 登录页 | 保留不变 | 不变 |

> **"增强"含义**: 在现有页面基础上扩展功能（如新增卡片、支持更多设备类型、新增告警类别），但不改变页面的核心交互逻辑和数据结构，确保向后兼容。
>
> **"迁移"含义**: 页面功能完全不变，仅调整其在导航菜单中的归属位置，以适配 V4.0 重构后的导航框架（如能源相关页面从统一的 /energy 下拆分到"供配电管理"和"节能中心"两个一级入口）。

## 2. 保留的后端功能需求

以下功能需求编号继承自旧版 PRD（V3.1），在 V4.0 中全部保留。这些需求构成了系统的核心业务能力，V4.0 在此基础上新增 FR-13 及以后的功能需求。

| 需求编号 | 功能模块 | 详细内容 | V4.0 策略 |
|----------|----------|----------|-----------|
| FR-1 | 用户认证与权限管理 | JWT 登录/登出/刷新、三级 RBAC、用户 CRUD、登录历史 | 完整保留，作为所有新模块的认证基础 |
| FR-2 | 设备与点位管理 | 设备 CRUD、点位 CRUD（AI/DI/AO/DO/CALC）、点位分组、实时数据表 | 完整保留，新设备类型通过扩展设备 CRUD 纳入 |
| FR-3 | 实时监控 | 5秒周期采集、WebSocket 三通道推送、仪表盘概览 | 完整保留，新设备数据自动通过 Point 体系纳入 |
| FR-4 | 告警管理 | 4级告警、阈值配置、确认/解除、声音通知、统计趋势、CSV导出 | 完整保留，扩展告警类型以覆盖新增子系统 |
| FR-5 | 能源管理 | PUE 监控、配电拓扑、能耗统计、需量管理、电价管理、功率曲线 | 完整保留，路由归属调整至"供配电管理" |
| FR-6 | 节能优化 | 6种分析插件、方案模板、节能机会识别、执行追踪 | 完整保留，路由归属调整至"节能中心" |
| FR-7 | 资产管理 | 资产台账、机柜管理、生命周期、维保记录、盘点、统计 | 完整保留，机柜管理增强 U 位实时管理 |
| FR-8 | 运维管理 | 工单全生命周期、巡检计划/任务、知识库 | 完整保留，不做变更 |
| FR-9 | 报表统计 | 模板管理、日/周/月报表、CSV/JSON导出、同比环比 | 完整保留，扩展新模块报表模板 |
| FR-10 | 容量管理 | 空间/电力/制冷/承重容量监控、规划 | 完整保留，路由归属调整至"基础设施" |
| FR-11 | VPP 虚拟电厂 | 电费分析、可调负荷、调度优化 | 完整保留，不做变更 |
| FR-12 | 系统管理 | 配置 CRUD、数据字典、许可证、日志 | 完整保留，不做变更 |

> **保留策略说明**: V4.0 不修改任何已有 FR 的接口契约（API 路径、请求/响应格式）。新增功能通过新的 FR 编号（FR-13+）独立实现，与已有功能解耦。部分 FR 的前端路由归属会调整，但后端 API 路径保持不变。

## 3. 保留的 Pinia Store

前端状态管理层（Pinia Store）在 V4.0 中全部保留。新增子系统的状态管理通过新建 Store 实现，不修改已有 Store 的数据结构。

| Store | 用途 | V4.0 处理 | 影响范围 |
|-------|------|-----------|----------|
| useUserStore | 认证、token、权限 | 保留不变 | 无影响 |
| useAppStore | 主题、侧边栏、标签页 | 保留，更新导航菜单结构 | 菜单配置数据变更，Store 接口不变 |
| useAlarmStore | 活动告警、告警计数 | 保留，扩展告警类型 | 告警类型枚举扩展，核心逻辑不变 |
| useRealtimeStore | 实时点位数据 | 保留不变（新设备数据通过 Point 体系自动纳入） | 无影响 |
| useEnergyStore | 功率数据、PUE、建议 | 保留不变 | 无影响 |
| useBigscreenStore | 3D 场景、图层、面板 | 保留不变 | 无影响 |
| useOpportunityStore | 节能机会、执行计划 | 保留不变 | 无影响 |

> **"扩展"含义**: 对于标注"扩展"的 Store（如 useAlarmStore），V4.0 会在现有数据结构中增加新的枚举值或可选字段，但不会修改已有字段的类型或语义，确保依赖这些 Store 的现有组件无需改动。

## 4. 保留的技术架构

V4.0 不更换任何核心技术栈组件，确保开发团队无需学习新框架，降低升级风险。

| 层级 | 技术选型 | V4.0 处理 |
|------|----------|-----------|
| 前端框架 | Vue 3 + TypeScript + Vite + Element Plus | 不变 |
| 后端框架 | FastAPI + SQLAlchemy 2.0 (async) + Pydantic v2 | 不变 |
| 数据库 | SQLite (开发) / PostgreSQL (生产) | 不变 |
| 代理层 | Express + http-proxy-middleware | 不变 |
| 实时通信 | WebSocket 三通道推送 realtime/alarms/system | 不变 |
| 数据模拟 | 5秒周期模拟数据生成 | 扩展新设备类型的模拟数据 |

> **技术架构保留的意义**: 保持技术栈一致性意味着所有现有的开发工具链、CI/CD 流程、部署脚本、测试框架均可直接复用。V4.0 的新增功能（如制冷监控、安防系统）作为新模块接入现有架构，而非引入新的技术依赖。

## 5. V4.0 影响总结

### 完全不变的部分

以下模块在 V4.0 中不做任何修改，开发者可以放心跳过：

- 前端页面：点位管理、历史数据、系统设置、工单管理、巡检管理、知识库、VPP 分析、登录页（共 8 个页面）
- 后端功能：FR-8（运维管理）、FR-11（VPP 虚拟电厂）、FR-12（系统管理）
- Pinia Store：useUserStore、useRealtimeStore、useEnergyStore、useBigscreenStore、useOpportunityStore（共 5 个 Store）
- 技术架构：前端框架、后端框架、数据库、代理层、实时通信（全部不变）

### 保留但增强的部分

以下模块保留核心逻辑，在此基础上做功能扩展：

- 监控仪表盘 — 增加动环综合概览卡片（制冷/UPS/安防）
- 设备管理 — 扩展设备类型（UPS/空调/传感器/门禁等）
- 告警管理 — 扩展告警类型（安防/消防/环境类）
- 报表分析 — 扩展新模块报表模板
- 机柜管理 — 增强 U 位实时管理
- useAppStore — 更新导航菜单结构
- useAlarmStore — 扩展告警类型枚举
- 数据模拟器 — 扩展新设备类型的模拟数据

### 保留但重新组织的部分

以下页面功能不变，仅调整导航归属以适配 V4.0 新导航框架：

- 能源相关 6 个页面 → 拆分至"供配电管理"和"节能中心"两个一级入口
- 资产台账、容量管理 → 移至"基础设施"一级入口
- 数字孪生大屏 → 保留现状，后续由独立系统替代
