## 0. 摘要（一页纸）

国家已将"**算电协同**"写入 2026《政府工作报告》，并要求**到 2025 年底国家枢纽节点新建数据中心绿电占比超过 80%**、储能"标配"、有序推进"绿电直连"。考核正从"唯 PUE 论"转向 **PUE + 绿电占比 + CUE + 可调节负荷** 综合体系。

**系统现状：源网荷储调度底座已基本就绪**（V3.0 电费综合优化系统：`DispatchableDevice` 6 类可调度负荷、`DispatchSchedule` 96 时段、`PVSystemConfig`/`StorageSystemConfig`、多站点 `Site`、`VppDispatch` VPP 调控、`optimizer.py` 已含 pulp MILP、RL 优化器；以及负荷转移、预冷 RC 模型、需量管理、PUE）。

**真正要补的三块空白 + 一次重构：**

| 待补 | 内容 |
|------|------|
| 🟢 绿电/碳**语义层** | 给光伏/储能/电网贴 `is_renewable/碳因子` 标签；绿电占比（**口径合规可审计**）、CUE（location/market 双口径）、绿证/绿电交易、24/7 CFE 逐时匹配 |
| 🔵 算力**作业柔性层** | "可中断 AI 作业"调度（叠加在刚性设施层之上，含 **ramp 暂态安全约束**） |
| 🧠 协同**编排器** | 统一编排既有执行栈（single-writer + 仲裁链），目标函数含碳/绿电/**制冷能耗/需量** |
| ♻️ 目标函数**重构** | 这是全案"总开关"：缺制冷/需量两维会自动产生"正午堆负荷"的错误 |

**三大主题**（对应三个"突出"）：
1. **突出绿电** —— 合规可审计的绿电占比 + 双口径 CUE + 绿证/绿电交易 + **24/7 CFE 小时级零碳匹配**（RE100 级卖点）。
2. **突出协同** —— 算力在【绿电富余 ∩ 自然冷却充足 ∩ 不创造需量尖峰】的时段运行，算力+储能+制冷+负荷转移统一编排。
3. **突出节能与交易** —— VPP 聚合参与需求响应/辅助服务 + 绿电/绿证交易 + 自然冷却/液冷/蓄冷节能，形成"省电费 + 赚响应 + 卖绿证 + 降碳(ESG)"。

> **诚实边界**：碳收益为**影子价/ESG 避免排放（非碳市场可交易资产）**；算力执行一期为**开环（建议+模拟）**；动态碳因子一期为**模拟/代理**（官方仅年度因子）；绿电直连一期仅做**计量与消纳建模**（不含一次工程）。详见 §8.4。

## 2. 什么是算电协同（概念框架）

算电协同 = 在 **源（绿电）—网（电价/碳/DR）—荷（IT+制冷）—储（储能/蓄冷）—算（算力作业）** 之间做**时空联合优化**。

```
        ┌──────────── 协同编排器（Orchestrator，新增）────────────┐
        │ 目标: min(电量电费 + 需量电费 + 制冷电费(COP) + 碳排放×影子碳价) │
        │        − DR收益 − (绿电溢价 − 偏差考核)                        │
        │ 约束: 算力SLA + 热(风冷RC+ASHRAE+露点 / 液冷CDU) + 储能SOC/PCS │
        │        + 15min需量红线 + UPS≤80%+ramp + N+1 + 自然冷却可用度    │
        │ 输出: 仅编排器可写 DispatchSchedule(96×15min) + 仲裁优先级链    │
        └─────────────────────────────────────────────────────────────┘
   信号↑(绿电出力/碳因子/电价/DR/自然冷却可用度/需量)   ↓指令(作业/储能/制冷/负荷)
 ┌────────┬──────────┬──────────────┬──────────┬──────────────────┐
 │  源    │   网     │   荷          │   储      │   算（新增柔性层）│
 │ 光伏✓  │ 电价✓    │ 制冷✓(COP感知)│ 储能✓+PCS │ AI训练/批处理     │
 │ 风电*  │ 碳因子*  │ UPS(刚性)     │ 蓄冷(分层)│ (可中断,带ramp约束)│
 │ 电网✓  │ DR/VPP✓  │ IT(刚性)      │           │ 在线推理(刚性)    │
 └────────┴──────────┴──────────────┴──────────┴──────────────────┘
   ✓=已有  *=需补绿电/碳语义
```

**三类协同动作（"追绿电"不是唯一目标）：**
- **时间协同**：把可中断作业 + 储能充电 + 预冷排到 **绿电富余 ∩ 自然冷却充足 ∩ 不抬需量** 的时段（通常是**夜间低湿球**，而非正午——见 §5.3 与 §10）。
- **空间协同**：一期单中心多 zone 迁移可迁移作业；跨站点预留。
- **源荷储算互动**：电网信号（频率/电价/DR）→ 编排器 → 算力降载 + 储能放电 + 制冷预冷的组合响应。

§6 每个 KPI 必须标注其计量点来源；缺计量点的指标标记"估算/不可审计"。

#### 5.1.4 核心算法（口径纠错 + 防重复计算）
- **绿电占比（合规口径，删除"储能折算"）**：
  ```
  renewable_ratio = (自发自用绿电 + 绿电交易电量[证电合一] + 核销绿证电量[证电分离]) / 总用电
  约束: 储能不进分子(储能贡献记入"就地消纳率/弃电率"与"CFE逐时匹配率");
        三类来源按 cert_id/trade_id 互斥去重; renewable_ratio ≤ 1
  ```
  - **达标口径明确**：80%（行业专项）与 RPS 消纳责任权重（法定下限）**分别核算、分别预警**。
- **碳权属唯一性原则**：绿证/绿电的环境权益一旦用于 market-based 范围2扣减或对外出售，**不得再计入任何碳资产**；`green_trades.revenue` 与 `cue_history` 碳减排**不可相加**为同一收益口径。
- **CUE 双口径**：
  ```
  CUE_location = Σ(用电量_i × 电网平均因子) / IT用电   # 物理真实, 不因买证变化, 短期不可能趋零
  CUE_market   = Σ(用电量_i × 市场化因子_i) / IT用电   # 绿电覆盖≈0, 未覆盖用 residual mix
  ```
- **24/7 CFE 逐时匹配率（差异化卖点）**：
  ```
  CFE_hourly = Σ_h min(零碳供给_h, 负荷_h) / Σ_h 负荷_h   # 对标 RE100/Google 24/7
  ```
- **绿证合规核销闭环**：用电量 → RPS 应消纳量 / 80% 目标量 → 绿电交易(自带证)抵充 + 绿证核销(唯一性去重，核销后锁定不可逆) → 年度缺口预警 → 写 `effect_reports`。

#### 5.1.5 绿电直连/直供/隔墙售电（分模式，勿混谈）
`Site`/拓扑 + `connection_mode(公网并网|绿电直连专线|直供|隔墙售电)`、`direct_metering_point`、`backup_capacity_fee`、`self_consumption_ratio`。带政策约束校验（自发自用比例红线、直连电量不与公网购绿对同一负荷重复计绿）。**一期若仅并网，"真·绿电直连专线"列 §8 预留（不含一次工程/继电保护）。**

**新增 API**：`/green/ratio`、`/green/cfe`、`/carbon/cue`(双口径)、`/carbon/factors`、`/green/certificates`、`/green/trades`。

### 5.3 🧠 算电协同编排器（突出协同·目标函数重构 + 治理）

#### 5.3.1 目标函数（重构——全案总开关）
```
min  Σ_t [ 电量电费(P_grid,t · price_energy,t)
          + 制冷电费( Q_IT,t / COP(t_outdoor,t) · price,t )      # 新增: 消除"正午堆负荷"偏置
          + 碳排放(P_grid,t · 边际碳因子,t) × 影子碳价 ]          # 影子价, 不产生现金流
     + 需量电费( max 15min 滑动需量 × demand_price )             # 新增: 消除"省电量涨需量"
     − DR收益
     − ( 绿电溢价收益 − 偏差考核费 )                              # 净额, 非毛收益
```
- COP 复用 `precool/thermal_model._get_seasonal_cop()`；需量电费复用 `MonthlyStatistics.demand_cost`。
- **碳价 = 内部影子价**（多目标权重，体现降碳偏好，**不计入现金收益**，见 §8.4）。

#### 5.3.2 约束集（安全红线，逐条对应代码）
- **算力 SLA**：deadline / 最短运行时 / 算力供给。
- **热约束（按 cooling_type 分流）**：
  - 风冷 → RC 模型 + ASHRAE 进风 18–27℃ + **温度裕度<2℃ 禁转** + **送风温 ≥ 露点 + 3℃（防结露）** + RH 维持推荐窗。
  - 液冷 → **独立约束**（二次侧供液温 ≤ 设定、ΔT 上限、CDU 换热余量），**不进 RC**。
- **储能**：SOC ∈[min,max]、PCS 视在功率 S=√(P²+Q²) ≤ 额定、并网点容量、C-rate、防孤岛。
- **需量**：15min 滑动需量 ≤ `demand_target`（拉载+储充+预冷叠加净功率不得击穿）。
- **配电/UPS**：稳态 ≤80% + 算力 ramp 暂态（§5.2）+ N+1（升/降双向）。
- **自然冷却可用度**：`free_cooling_availability(t)=f(室外干球/湿球/湿度)`——充足时抬高送风上限、放大可时移制冷量、优先排入可时移作业。

#### 5.3.3 协同动作
- **时间协同**：可中断作业/储充/预冷排到【绿电富余 ∩ 自然冷却充足 ∩ 不抬需量】窗口（多为夜间低湿球）。
- **空间协同**：一期 zone 级；跨站点预留。
- **源荷储算互动**：电网信号 → 算力降载 + 储能放电 + 制冷预冷组合响应。

#### 5.3.4 运行时与调度权威（架构治理）
- **运行时**：编排器 = `app.main` lifespan 注册的**后台 asyncio 周期任务**（仿 `diagnosis/scheduler.py`），**stateless re-compute from DB**，重启从"当前 time_slot 之后 pending 计划"续跑（幂等）；**勿用内存单例**（不沿用 `realtime_dispatch.py` 内存模型）。`/coordination/plan|execute|simulate` 仅作读/手动触发/what-if 入口。
- **调度唯一权威（single-writer）**：`DispatchSchedule` **仅编排器可写**；子栈（precool/vpp/load_shift）降级为向编排器**提交候选计划(proposal)**，自有表保留为内部意图/执行回执。`DispatchSchedule` 加 `UniqueConstraint(schedule_date,device_id,time_slot)` + `plan_version` + `source`。
- **仲裁优先级链**：**安全约束(温度/N+1/UPS/ramp) > 在线业务 SLA > 电网强制 DR > 需量红线 > 经济目标(电费/碳/绿电)**。冲突时高优先级胜出，低优先级让路并写 `AuditLog` 原因。编排器接管既有点对点仲裁（如 `VppDispatch.aborted_schedule_id`），子栈不再自行 abort。
- **并发/事务**：单轮落库一个事务边界（全成功或回滚 + `plan_version` 递增）；`DispatchSchedule`/`cue_history`/`effect_reports` 用唯一约束幂等 upsert 或 `version` 乐观锁（复用既有范式）。
- **两级时间尺度**：编排器 15min 经济调度（对齐 `time_slot 0–95`）；下发制冷前经 `thermal_model` 5min 轨迹校验 + **≥20min 滞后预启**（对应既有制冷联动），避免"15min 拉载、制冷 20min 才跟上"的瞬时越温。

#### 5.3.5 求解器（复用，非新依赖）
一期**直接复用 `optimizer.py`（已含 pulp MILP：96 时段/SOC/充放互斥/需量/CBC+启发式回退）**，目标函数加碳/绿电/制冷/需量项即可；仅需把 pulp/CBC 转正写进 `requirements.txt` 并打包。RL 优化器/`opportunity_engine` 作为补充/对照。

**新增 API**：`/coordination/plan`、`/coordination/execute`(走审批)、`/coordination/simulate`。

## 8. 闭环、边界、降级与诚实声明

### 8.1 闭环
- 接入既有闭环 `energy_opportunities → execution_* → effect_reports/measure_baselines → RL/feedback_learning`，**不另画**。
- 绿电/碳/算力核算指标写入 `effect_reports`（事后核验绿电占比是否真达 80%、CUE 是否真降）。
- 绿证合规闭环：用电 → RPS/80% → 抵充核销(唯一性) → 缺口预警。
- **MRV/对外披露**：保留原始计量不可篡改留痕、碳因子版本与来源、国家绿证系统核销凭证(`gec_system_ref`)、口径声明(location/market)、第三方核查状态。

### 8.2 边界条件
- **绿电 80% 达不到 + 作业 SLA 不允许延迟时**：保 SLA 优先于保绿电占比；可中断作业让路、在线业务不让。
- **光伏失稳兜底**：追光伏拉载须留储能/可中断作业作为骤降快速回退（防需量尖峰）。
- **跨站点**：`Site` 缺站间时延/带宽/算力余量 → 一期仅单中心多 zone。
- **时段/告警**：统一对齐 `time_slot 0–95`；告警以服务端 5 级为准。
- **安全红线不可破**：算力功率变化须过 `datacenter_shift_strategy` + `check_compute_ramp_constraint()` + 热/储/需量校验。

### 8.3 外部信号降级矩阵
| 外部依赖失效 | 降级行为 |
|------------|---------|
| 碳因子不可得 | 回退上一有效值/年度因子，标 degraded；CUE 仅展示不参与硬告警 |
| 现货/实时价不可得 | 回退静态分时电价（复用 `optimizer.py` 兜底价），只做电费优化 |
| DR 信号不可得 | 不响应 DR，保持基线 |
| 算力 actuator(K8s) 不可得 | 只读建议（一期默认即此） |
| 缺省安全态 | 回退"静态电价纯电费优化 + 只读建议" |

### 8.4 诚实边界声明（避免 Demo 被当成"已实现"）
- **碳**：DC 非全国碳市场履约主体、用电属范围2且扩围明确剔除范围2、无 DC 负荷调度/绿电消纳 CCER 方法学 → **碳价=内部影子价（不产生现金流）、碳减排=避免排放/ESG 口径，非可交易碳资产**。
- **碳因子**：官方仅年度（全国/区域/省级）；**小时级动态碳因子一期为模拟/代理**。
- **算力执行**：一期**开环**（建议+模拟），不得宣称"已闭环控制"。
- **绿电直连**：一期仅**计量与消纳建模**，专线/并网点/继电保护/防孤岛属一次工程，不在软件范围。
- **蓄冷/余热**：RC 预冷为分钟级毛刺工具；大容量蓄冷罐、余热回收列**条件性/预留**。

## 10. Demo 闭环剧本（已按暖通/电气修正——夜间优先，非正午堆载）

**场景：内蒙古某零碳算力园区一天（源网荷储算协同）**
1. 模拟器产出：光伏(正午高)、风电(夜间高)、室外温湿度、电网碳因子、分时/现货电价、一次午间"填谷"DR 事件。
2. **白天正午**：光伏富余但**室外温度高、COP 低、自然冷却关闭** → 编排器**不无脑堆训练**；仅在制冷边际代价可接受范围内适度拉载 + **储能充电吸纳光伏** + 适度预冷；同时**监控 15min 需量不被击穿**（光伏骤降由储能/可中断作业兜底）。绿电占比上升但以"消纳光伏"为主。
3. **夜间**：风电高 + **室外低湿球、自然冷却拉满、COP 最高** → **优先把可中断 AI 训练搬到此窗口**（绿电∩自然冷却∩低需量三优），CUE_market 下降、CFE 逐时匹配率上升。
4. **晚高峰高价高碳**：释放储能 + 训练降载 + 蓄冷释放 → 削峰、避高碳、拿 DR 收益。
5. 大屏滚动（**现金区 vs 环境区分开**）：现金区=电量电费节省/需量电费/DR 收益/绿电溢价；环境区=绿电占比/CFE 逐时匹配率/CUE 双口径/避免排放(tCO₂, 注"ESG 口径")/自然冷却小时数。

> 此剧本对标乌兰察布/克拉玛依/庆阳（低温干燥、自然冷却充沛），物理自洽、经得起标杆评审。

## 11. 风险与边界

| 风险 | 应对 |
|------|------|
