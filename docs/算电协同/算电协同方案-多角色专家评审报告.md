## 0. 总体结论

**方向与工程骨架（绿电碳语义层 + 算力柔性层 + 编排器复用）成立，但 V1.1 作为"领域方案"尚不达标——五个专业各自发现了会导致"指标不可审计 / 物理上反效果 / 并网踩红线 / 收益高估 / 无法落地"的硬伤。** 综合判断：**V1.1 = 可讲故事的蓝图，距"敢并网、可审计、能变现"还差一轮领域修正（V1.2）。**

最强信号是**跨专业交叉验证**——两个以上独立专家指向同一问题（见 §1）。这些是最高置信、必须先改的。

| 角色 | 一句话结论 | 致命级发现数 |
|------|-----------|------------|
| 碳交易员 | 碳维度可信度**中低**：把不持有的碳资产当变现来源 | 4×P0 |
| 绿电交易员 | 存在 P0 口径错误：**"储能绿电折算"虚高占比 + 证电双重声明**，过不了核查 | 2×P0 |
| 电气工程师 | 把电力电子/暂态当软件抽象：**ramp 冲击 / PCS 缺失 / 需量反噬 / 计量不闭合** | 4×P0 |

| 系统架构师 | 方向对，但**调度权威/运行时/审批授权**五面空白 | 3×P0 |

## 1. 交叉验证的高置信问题（≥2 专业独立指向，最优先）

### 🔴 CX-1 「正午追绿电」是物理与经济双重错误（暖通 + 电气 双独立确认）
- **暖通**：正午室外温度最高 → 冷机 COP 最低（系统自有参数 `_get_seasonal_cop()`：正午 2.8 vs 夜间 4.0）→ 同样 IT 发热**制冷电耗上升约 43%**，自然冷却窗口正午关闭。把训练堆到正午，**降碳收益被 PUE 恶化吃掉甚至反噬**。
- **电气**：正午"拉训练 + 储能充电 + 预冷"三个增功率动作叠加，且光伏可被云层分钟级打断 → 缺口瞬间打到电网 → **可能创造全月最高 15 分钟需量 → 需量电费暴涨**（"省了电量、涨了需量"）。
- **根因（共识）**：§5.3 目标函数 `min(电费 + 碳×碳价 − DR − 绿电)` **缺两个维度**：①制冷能耗/COP 项；②需量电费项。优化器只看到"正午绿电便宜+碳低"，看不到制冷塌方与需量尖峰，必然把负荷堆正午——**是目标函数缺维导致的系统性偏置**。
- **必修**：目标函数重构（见 §3 P0-1）；新增"追自然冷却窗口"为与"追绿电"并列的协同目标；§10 Demo 改为"**夜间低湿球 + 绿电时段**优先时移训练"，删除"正午无脑拉满"。

### 🔴 CX-2 头号 KPI（绿电占比/CUE）当前口径不实、不可审计（绿电 + 碳 + 电气 三独立确认）
- **绿电交易员**：§5.1 公式 `renewable_ratio=(自发绿电+外购绿电+储能绿电折算)/总用电` 中**"储能绿电折算"是概念错误+重复计算**——储能不产生绿色属性，只时移且有 10–15% 往返损耗，同一度绿电充放各计一次 → 占比虚高。
- **碳交易员**：CUE 缺 **location-based（电网平均因子）vs market-based（扣绿电）双口径**；绿电/绿证/碳减排三本账**无 double-counting 设防**。
- **电气工程师**：renewable_ratio/CUE 各分量**未绑定真实计量点**，缺关口表/光伏并网表/储能双向表/IT 侧表四类必备计量，**指标不可审计**（而 80% 是要被第三方核查的合规红线）。
- **必修**：绿电占比公式纠错 + 双口径 CUE + 计量点闭环 + 去重唯一性（见 §3 P0-3）。**这条最危险——整个方案的卖点就是合规，口径不实则一票否决。**

### 🔴 CX-3 把"物理/市场"当"软件字段"——可演示≠可落地（电气 + 暖通 + 碳 + 绿电 四方共识）
- 算力 ramp 暂态、储能 PCS/并网、RC 预冷蓄冷容量、液冷热模型、碳资产、绿电交易结算——**V1.1 普遍简化成了数据字段，丢失了领域约束**。
- 各方独立给出同型批评："软件架构克制专业，但把电力电子和暂态物理/市场机制当成了软件抽象"。
- **必修**：补齐各域的物理/市场约束（见 §3 各 P0/P1）。

## 2. 五个角色的核心发现（精简版，完整发现见各专家原始评审）

### 2.1 碳交易员
- **P0** 把"碳价/碳减排(tCO₂)变现"当可交易资产——**定性错误**：DC 非全国碳市场履约主体，用电属范围2且 2025 扩围**明确剔除范围2**；碳价只能是**内部影子价（不产生现金流）**，碳减排只能算**避免排放/ESG 口径**。
- **P0** 绿电/绿证/碳减排 **double-counting** 无设防（碳权属唯一性缺失）。
- **P0** CUE 缺 location/market-based 双口径（"绿电≈0"仅 market-based 成立；location-based 受电网约束**不可能趋零**，"CUE 趋近零碳"是夸大）。
- **P0** **边际碳因子（调度用）vs 平均碳因子（核算用）** 口径冲突，`carbon_factors` 单字段两用。
- **P1** 中国官方**无小时级动态碳因子**（仅年度全国/区域/省级），方案的逐时碳曲线一期只能标注"模拟/代理"。
- **P1** **CCER 无 DC 负荷调度/绿电消纳方法学**，不能开发为可交易碳资产（过度承诺）；I-REC 与国内 GEC 混表。
- **P1** 缺 MRV（监测-报告-核证）/审批留痕/对外披露口径。

### 2.2 绿电交易员
- **P0** "储能绿电折算"计入占比分子（见 CX-2）；储能应归"就地消纳率/弃电率"与"小时级匹配"。
- **P0** 绿电（证电合一，自带证）vs 绿证（证电分离）**双重声明风险**；**80% 达标口径未定义认什么**。
- **P1** `green_trades` 字段不足以真实结算：缺**绿电溢价、合约结构、偏差考核（±2~5% 免考核带 + 偏差 penalty）、关口计量**——目标函数"绿电收益"应为 `溢价收益 − 偏差考核费`，非净收益直填。
- **P1** "绿电直连/直供/隔墙售电"混为一谈，低估 650 号文政策门槛（自发自用比例、备用费、环境属性归属）。
- **P1（机会）** 小时级 renewable_ratio **天然支持 24/7 CFE 逐时匹配**——RE100/出口客户高价值卖点，方案没讲出来。
- **P2** RPS 消纳责任权重（法定下限）vs 80%（行业专项）口径混用；核销唯一性闭环不全。

### 2.3 电气工程师
- **P0** **算力 ramp 暂态绕过现有安全校验链**：`datacenter_shift_strategy.py:62` 对 IT/UPS 直接 `return 0.0`（从不校验温度/N+1/UPS），§8.2"算力功率变化仍须通过校验"是**无法兑现的承诺**；缺 dP/dt 动态约束。
- **P0** 储能调度缺 **PCS（变流器）/并网点/防孤岛/视在功率 kVA** 实体——不是"复用充放电参数"就能并网。
- **P0** **"正午拉载"制造需量尖峰**（见 CX-1）；目标函数需拆出 `demand_cost`；缺光伏失稳兜底。
- **P0** 计量体系未落到真实 `meter_points`（四类必备计量点），指标不可审计（见 CX-2）。
- **P1** 光伏逆变器/储能 PCS 的**谐波/无功/功率因数**影响既有力调电费（`MonthlyStatistics.power_factor_adjustment`）；"省有功却被罚力调"陷阱。
- **P1** 绿电直连电气实质（专线/并网点/继电保护/防孤岛）被当"建模"低估。

### 2.4 暖通工程师
- **P0** **追绿电(正午) vs 制冷效率冲突 + 目标函数无 COP/制冷项**（见 CX-1）。
- **P0** 严重**高估 RC 预冷蓄冷能力**（系统自有文档已承认"仅几个百分点、几十分钟"）；小时级时移制冷需**专用蓄冷罐**（新增资产），不能与 RC 预冷混谈。
- **P0** **液冷与空气 RC 模型不兼容**：液冷是 CDU/二次侧冷媒回路，无机房空气测点，ASHRAE 进风约束不成立；须按 `cooling_type` 分流建模。
- **P0** **结露/湿度约束丢失**（自有文档已有"送风温≥露点+3℃"，V1.1 反而回退）；"追绿电深预冷"在高湿正午是结露高风险。
- **P0** **自然冷却未进协同决策**——对乌兰察布/庆阳/克拉玛依等低温干燥标杆站点，**自然冷却小时数才是最大节能杠杆**，方案却只在 §5.4 一笔带过（本末倒置）。
- **P1** 余热回收忽略**品位（低品位需热泵提温）+ 消纳侧（就近热用户/季节需求）**；液冷才利于高品位回收。
- **P1** 15min 编排粒度与**制冷滞后 20min、预冷 5min 轨迹**不匹配，会掩盖瞬时温度越线。

### 2.5 系统架构师
- **P0** **调度唯一权威/冲突仲裁缺失**：`DispatchSchedule` 无唯一约束、子栈各自产计划（precool/vpp/load_shift/execution）；编排器"统一输出"≠子栈"停止自产"。需 single-writer + proposal 模型 + 仲裁优先级链。
- **P0** **编排器运行时架构未定义**：应=后台 asyncio 周期任务（仿 `scheduler.py`）、**stateless re-compute from DB、重启续跑**；勿沿用 `realtime_dispatch.py` 的内存单例。
- **P0** **trading/dispatch 审批授权审计缺失**（涉钱高危）：复用 `CommandApproval`/`AuditLog`，operator 发起 / admin 审批 / viewer 只读。
- **P1** 并发写 `DispatchSchedule`/`effect_reports` 无事务/幂等/乐观锁（`version` 范式项目已有）。
- **P1** 外部依赖**降级矩阵**只覆盖算力，漏电价/碳因子/DR/actuator。
- **P1** 迁移与回滚策略缺失（热表加列 + 多新表，energy.py churn 大）。
- **P1** `site_id` 未贯穿新表（二期跨站点会痛改；新表应一律 site_id 化）。
- **P2（事实订正）** **`optimizer.py` 已有完整 pulp MILP 实现**（96 时段/SOC/需量约束/CBC+启发式回退），**MILP 不是二期新依赖**——V1.1 §5.3/§11 表述错误，一期即可复用，仅需把 pulp/CBC 转正打包。

## 4. 重点 P1（V1.2 应一并处理）

- **碳因子 marginal/average 分离**：`carbon_factors` 加 `factor_type(average|marginal)`；调度用边际（不可得→绿电出力代理并声明），核算用平均；`source` 加 `proxy_simulated`，声明官方仅年度因子。
- **绿电交易真实结算字段**：`green_trades` 加 `contract_id/contract_type/delivery_curve/green_premium/contracted_volume/actual_volume/deviation_volume/deviation_band/deviation_penalty/metering_point_id`。
- **24/7 CFE 卖点**：§6 KPI 加"逐时匹配率 CFE Score"，`cue_history` 加 `cfe_hourly_score`；§0/§10 升级叙事为"年度80% → 小时级零碳匹配"。
- **绿电直连三模式拆分**：Epic 40 拆"绿电直连/直供/隔墙售电"，Site 加 `connection_mode/direct_metering_point/backup_capacity_fee/self_consumption_ratio`；一期仅并网则把"真·直连专线"列预留并注明"不含一次工程与保护设计"。
- **蓄冷分层**：§5.4 区分"RC 预冷（分钟级/毛刺级削峰）"与"专用蓄冷罐（小时级/MWh/新增资产/预留）"。
- **余热回收品位+消纳约束**：净收益=售热−热泵提温电费−输配损失；一期列条件性/预留。
- **两级时间尺度**：编排器 15min 经济调度，下发制冷前经 `thermal_model` 5min 轨迹校验 + ≥20min 滞后预启。
- **架构治理**：并发乐观锁（复用 `version` 范式）；外部信号降级矩阵（碳因子/现货价/DR/actuator 逐条）；Alembic 迁移分组+独立 downgrade（新列一律 nullable+default）；新表一律 `site_id` 化。
- **功率因数/THD**：§6 加电能质量 KPI，与既有力调电费联动。

## 6. 结构性建议（V1.2 的形态）
