## 1. 现状与设计原则

## 1.1 现状结论（已确认）

- `constraint_checker.py` 中 UPS 与 IT 相关检查仅为 TODO + warning，占位未落地。
- `ConstraintEditor.vue` 未提供 IT 负载占比约束和 UPS 容量约束配置 UI。
- 制冷联动（后端 `cooling_linkage_service.py` + 前端配置/监控页）已完整实现，可复用其“配置 + 校验 + 监控”的实现路径。

## 1.2 关键兼容问题（必须先处理）

当前代码存在字段命名不一致：

- 模型：`ShiftConstraint.constraint_params`（`backend/app/models/load_shift.py`）
- Schema/算法：大量使用 `constraint_config`
- 约束服务：写 `params` 到 `constraint_params`

**风险**：若不统一，新增约束即使保存成功，算法可能读不到配置。  
**方案**：Phase 1 中完成统一（推荐统一为 `constraint_config`，并做兼容过渡）。

## 1.3 约束设计原则

1. 安全优先：UPS 过载校验为硬约束，默认拒绝执行。  
2. 可解释：返回“当前值、阈值、建议调整值”。  
3. 可配置：安全系数、可转移比例、超限策略可按站点调整。  
4. 可回放：校验输入和结果落到执行记录，便于审计。  
5. 与现有风格一致：沿用 `ConstraintChecker`、`ShiftConstraintConfig`、`ConstraintEditor` 现有结构。

## 3. Phase 2（后端实现）

> 目标：在可行性分析中真正执行 IT/UPS 校验，输出可执行建议。

## 3.1 IT 负载占比计算逻辑

## 3.1.1 核心公式

来自技术文档 11.5.1：

```text
最大可转移功率 = 总功率 × (制冷占比 × 0.4 + 其他占比 × 0.6)
```

## 3.1.2 计算步骤

1. 查询当前总功率 `total_power`。  
2. 查询/计算 IT、制冷、配电、其他功率占比。  
3. 计算 `it_ratio = it_power / total_power`，校验是否在 `[it_load_ratio_min, it_load_ratio_max]`。  
4. 计算 `max_transfer_power`。  
5. 与请求 `target_shift_power` 比较：
   - 超限则 violation（硬约束）或 warning（软约束）。

## 3.1.3 代码示例（ConstraintChecker）

```python
async def _check_datacenter_load_constraints(self, request, constraints):
    violations, warnings = [], []

    # 1) 找 datacenter_load 约束
    dc_constraints = [c for c in constraints if c.constraint_type == ConstraintType.DATACENTER_LOAD]
    if not dc_constraints:
        return {"is_valid": True, "violations": [], "warnings": []}

    # 2) 查询实时负载分布（建议下沉到 service）
    dist = await self._query_datacenter_load_distribution()
    total_power = dist["total_power"]
    it_ratio = dist["it_power"] / total_power if total_power else 0

    for c in dc_constraints:
        cfg = c.constraint_config
        min_it = cfg.get("it_load_ratio_min", 0.6)
        max_it = cfg.get("it_load_ratio_max", 0.8)

        if not (min_it <= it_ratio <= max_it):
            violations.append({
                "constraint_id": c.id,
                "constraint_type": "datacenter_load",
                "violation_type": "it_ratio_out_of_range",
                "message": f"IT负载占比 {it_ratio:.2%} 不在范围 [{min_it:.0%}, {max_it:.0%}]",
                "current_value": it_ratio,
                "limit_value": {"min": min_it, "max": max_it},
            })

        cooling_ratio = cfg.get("cooling_ratio", dist["cooling_ratio"])
        other_ratio = cfg.get("other_ratio", dist["other_ratio"])
        cool_tr = cfg.get("cooling_transferable_ratio", 0.4)
        other_tr = cfg.get("other_transferable_ratio", 0.6)

        max_transfer_power = total_power * (cooling_ratio * cool_tr + other_ratio * other_tr)

        if request.target_shift_power > max_transfer_power:
            violations.append({
                "constraint_id": c.id,
                "constraint_type": "datacenter_load",
                "violation_type": "max_transfer_power_exceeded",
                "message": f"目标转移功率 {request.target_shift_power}kW 超过上限 {max_transfer_power:.2f}kW",
                "current_value": request.target_shift_power,
                "limit_value": max_transfer_power,
            })

    return {
        "is_valid": len(violations) == 0,
        "violations": violations,
        "warnings": warnings,
        "distribution": dist,
    }
```

## 3.2 UPS 容量检查逻辑

## 3.2.1 核心公式

来自技术文档 11.5.2：

```text
转移后峰值功率 ≤ UPS 额定容量 × safety_factor（默认 0.8）
```

## 3.2.2 计算步骤

1. 根据 `ups_device_ids` 查询 UPS 额定容量总和。  
2. 查询当前 UPS 负载功率。  
3. 计算转移后峰值：`post_peak = current_ups_load + incremental_peak_from_plan`。  
4. 校验 `post_peak <= rated_sum * safety_factor`。  
5. 超限处理：
   - `auto_adjust=true`：给出 `suggested_max_shift_power`；
   - `reject_on_exceed=true`：直接 violation。

## 3.2.3 代码示例

```python
async def _check_ups_capacity_constraints(self, request, constraints):
    violations, warnings = [], []
    ups_constraints = [c for c in constraints if c.constraint_type == ConstraintType.UPS_CAPACITY]

    for c in ups_constraints:
        cfg = c.constraint_config
        safety_factor = cfg.get("safety_factor", 0.8)
        ups_ids = cfg.get("ups_device_ids", [])

        rated_sum = await self._query_ups_rated_capacity_sum(ups_ids)
        current_load = await self._query_ups_current_load_sum(ups_ids)
        post_peak = current_load + request.target_shift_power
        max_allowed = rated_sum * safety_factor

        if post_peak > max_allowed:
            suggested = max(0.0, max_allowed - current_load)
            msg = f"UPS容量约束超限: 转移后峰值 {post_peak:.2f}kW > 允许值 {max_allowed:.2f}kW"

            if cfg.get("reject_on_exceed", True):
                violations.append({
                    "constraint_id": c.id,
                    "constraint_type": "ups_capacity",
                    "violation_type": "ups_overload",
                    "message": msg,
                    "current_value": post_peak,
                    "limit_value": max_allowed,
                    "suggested_max_shift_power": suggested,
                })
            else:
                warnings.append(msg)

    return {
        "is_valid": len(violations) == 0,
        "violations": violations,
        "warnings": warnings,
    }
```

## 7. 风险与回退方案

1. **字段命名不一致风险**：先加兼容属性，列名改造后置。  
2. **实时功率数据波动**：加入采样窗口（如最近 1-3 分钟均值）避免误判。  
3. **UPS 设备绑定不完整**：缺设备映射时降级为 warning + 管理员告警。  
4. **公式参数争议**：可配置化并记录版本号，避免硬编码冲突。  
5. **回退**：迁移脚本可逆；新约束类型可通过开关禁用，不影响旧逻辑。
