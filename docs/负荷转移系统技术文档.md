## 1. 系统概述

### 1.1 什么是负荷转移

负荷转移（Load Shifting）是一种用电优化策略，通过将部分用电负荷从**高电价时段**（尖峰/峰时）转移到**低电价时段**（谷时/深谷），在不改变总用电量的前提下降低用电成本。

### 1.2 系统目标

- **智能分析**：基于历史用电数据，自动识别可转移设备和最优转移比例
- **方案规划**：提供交互式转移方案配置，支持多设备、多规则组合
- **收益预估**：实时计算日/年节省金额，提供转移前后负荷对比曲线
- **执行管理**：从方案到执行的全生命周期管理，包含效果追踪

### 1.3 适用场景

| 场景 | 说明 |
|------|------|
| 峰谷电价套利 | 利用分时电价差异，将高价时段负荷转移至低价时段 |
| 需量管理 | 通过削峰填谷降低最大需量，减少基本电费 |
| 电网响应 | 配合电网调度，在高峰时段主动削减负荷 |

## 2. 核心概念与术语

| 术语 | 英文 | 含义 |
|------|------|------|
| 可转移功率比例 | Shiftable Power Ratio | 设备额定功率中可被转移的比例（0~1） |
| 柔性系数 | Flexibility Factor | 设备类型固有的负荷调节灵活程度 |
| 源时段 | Source Period | 负荷转出的高价时段（尖峰/峰时/平时） |
| 目标时段 | Target Period | 负荷转入的低价时段（平时/谷时/深谷） |
| 转移规则 | Shift Rule | 一条完整的转移指令：源时段 → 目标时段 + 功率 + 时长 |
| 置信度 | Confidence | 推荐值的可靠程度，取决于历史数据天数 |
| 关键负荷 | Critical Load | 不可中断或转移的重要设备（如 UPS、IT 服务器） |
| 典型日Profile | Typical Day Profile | 基于历史数据聚合的24小时功率曲线 |
|| 基线能耗 | Baseline Energy | 负荷转移前的能耗基准，用于计算实际节能效果 |
|| 三相平衡度 | Three-Phase Balance | 三相负荷不平衡度，影响中性线电流和变压器效率 |
|| 电能质量 | Power Quality | 包括谐波、功率因数等指标，影响电网稳定性 |

## 6. 核心算法

### 6.1 可转移比例智能推荐算法

这是系统的核心算法，位于 `DeviceRegulationService._calculate_recommendation()` 方法中。

#### 输入数据

| 数据 | 来源 | 说明 |
|------|------|------|
| `rated_power` | 设备基础信息 | 设备额定功率 (kW) |
| `avg_power` | `energy_hourly` 表聚合 | 历史平均功率 |
| `max_power` | `energy_hourly` 表聚合 | 历史最大功率 |
| `min_power` | `energy_hourly` 表聚合 | 历史最低功率 |
|| `peak_ratio` | `energy_daily` 表聚合 | 峰时用电能量占比（非功率占比） |
| `flexibility` | 设备类型查表 | 柔性系数 |
| `type_max` | 设备类型查表 | 类型最大可转移比例 |

> 若无历史数据，使用默认估算值：`avg = 0.7 × rated`, `max = 0.9 × rated`, `min = 0.3 × rated`

#### 理论基础

**四约束模型的数学原理**：

取 `min()` 而非加权平均的原因：
- 约束 1-4 代表四个**独立的安全边界**，任何一个超限都会导致系统失效
- 类似于木桶原理（短板效应），最紧的约束决定了系统的安全上限
- 加权平均会允许某些约束超限，导致安全风险

**安全系数 0.85 的来源**：
- 基于工程经验，留 15% 余量应对：
  - 数据波动：历史数据可能不代表未来极端情况
  - 设备老化：设备性能随时间衰减
  - 测量误差：传感器精度限制
- 参考标准：IEEE 1547-2018 分布式电源并网标准建议留 10-20% 余量
#### 四约束模型

算法基于**四个独立约束条件**取最小值，确保推荐值同时满足所有安全限制：

```
约束1: 最低功率约束
  constraint_1 = max(0, 1 - min_power / rated_power)
  含义: 设备历史最低功率不可削减，剩余部分才是可转移空间

约束2: 负荷波动空间
  constraint_2 = max(0, (max_power - avg_power) / rated_power)
  含义: 历史最大功率与平均功率之差，代表实际可削减的功率空间

约束3: 峰时转移潜力
  constraint_3 = peak_ratio × flexibility_factor
  含义: 峰时用电占比越高 × 设备越灵活 = 转移潜力越大

约束4: 设备类型硬上限
  constraint_4 = type_max_ratio
  含义: 该设备类型允许的最大转移比例（安全红线）
```

#### 综合计算

```
raw_ratio = min(constraint_1, constraint_2, constraint_3, constraint_4)

recommended_ratio = raw_ratio × 0.85    // 安全系数，留15%余量

// 范围校正
recommended_ratio = clamp(recommended_ratio, 0, type_max_ratio)

// 四舍五入到2位小数
recommended_ratio = round(recommended_ratio, 2)
```

#### 置信度评估（增强版）
置信度评估综合考虑数据天数、数据方差、季节性因素：
| 历史数据天数 | 数据方差 | 季节覆盖 | 置信度 | 含义 |
|------------|--------|--------|--------|------|
| >= 30 天 | CV < 0.2 | 跨季节 | **high** (高) | 数据充分且稳定，推荐值可靠 |
| >= 30 天 | CV >= 0.2 | 单季节 | **medium** (中) | 数据充分但波动大，建议观察 |
| >= 14 天 | CV < 0.2 | - | **medium** (中) | 数据基本够用，建议观察 |
| < 14 天 | - | - | **low** (低) | 数据不足，仅供参考 |
> **CV (Coefficient of Variation)** = 标准差 / 平均值，衡量数据波动程度

#### 变更判定

当推荐值与当前值的差异超过 **1%** 时，标记为有变更（`has_change = true`）。

#### 计算示例

假设一台 PUMP（水泵）设备：
- 额定功率: 100 kW
- 历史最低功率: 40 kW → constraint_1 = 1 - 40/100 = **0.60**
- 历史最大功率: 85 kW, 平均功率: 65 kW → constraint_2 = (85-65)/100 = **0.20**
- 峰时占比: 0.45, 柔性系数: 0.7 → constraint_3 = 0.45 × 0.7 = **0.315**
- PUMP 类型上限 → constraint_4 = **0.50**

```
raw_ratio = min(0.60, 0.20, 0.315, 0.50) = 0.20
recommended = 0.20 × 0.85 = 0.17
可转移功率 = 100 × 0.17 = 17 kW
```

### 6.2 设备转移潜力评估算法

位于 `LoadShiftAnalysisService._analyze_device_potential()` 方法中。

```
daily_shift_hours = 4                   // 假设每天可转移4小时
shift_efficiency = 0.8                  // 80%转移效率

monthly_shift_energy = shiftable_power × daily_shift_hours × 30 × shift_efficiency
monthly_saving = monthly_shift_energy × (peak_price - valley_price)
```

#### 分析参数默认值

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `peak_ratio_threshold` | 0.35 | 峰时用电占比超过此值才被视为有转移价值 |
| `min_shift_amount` | 50 kWh | 最小月转移电量阈值 |
|| `shift_efficiency` | 0.7 | 转移效率，考虑损耗来源：启停损耗 5%、过渡时段重叠 10%、实际执行偏差 15% |
| `device_min_power` | 5 kW | 设备最小功率阈值（低于此值忽略） |
| `min_device_shift_saving` | 100 元 | 单设备最小年节省金额阈值 |

### 6.3 转移方案收益计算

位于前端 `ShiftPlanBuilder.vue` 组件中的实时计算逻辑。

#### 单条规则日节省

```
单条规则日节省 = 转移功率(kW) × 转移时长(h) × (源时段电价 - 目标时段电价)
```

#### 汇总计算

```
总日节省 = Σ 所有设备所有规则的日节省
总年节省 = 总日节省 × 250    // 按250个工作日计
```
> **注意**：数据中心通常 365 天运行，但考虑到设备维护、负载波动等因素，按 250 个工作日计算是保守估计。如需精确计算，建议根据实际运行天数调整。

### 6.4 典型日功率Profile生成算法

位于 `DeviceRegulationService.get_device_typical_profile()` 方法中。

**数据源**: `energy_hourly` 表

**聚合方式**:
```sql
SELECT
  EXTRACT(hour FROM stat_time) AS hour,
  AVG(avg_power) AS avg_power,
  MAX(max_power) AS max_power,
  MIN(min_power) AS min_power,
  COUNT(*) AS record_count
FROM energy_hourly
WHERE device_id = ? AND stat_time >= (NOW - N days)
GROUP BY EXTRACT(hour FROM stat_time)
ORDER BY hour
```

**无数据时的模拟**: 基于额定功率生成钟形曲线
```python
base = rated_power × 0.6
avg_power = base × (0.8 + 0.4 × (0.5 - |hour - 14| / 24))
# 模拟白天高、夜间低的用电模式
```

**汇总指标计算**:
- 负载率 = 24h平均功率 / 额定功率
- 峰时用电占比 = (尖峰+峰时小时的能量之和) / 24h总能量

## 10. 收益计算模型

### 10.1 单条规则收益

```
日节省 = power(kW) × hours(h) × (source_price - target_price)(元/kWh)
```

**示例**: 将 30kW 从尖峰转移到深谷，持续 2 小时
```
日节省 = 30 × 2 × (1.40 - 0.20) = 72 元/天
```

### 10.2 年化收益

```
年节省 = Σ(所有规则日节省) × 250(工作日)
```

### 10.3 转移效率因子

后端分析时考虑 **80%** 的转移效率：
```
实际月节省 = 理论月节省 × 0.8
```
考虑因素：设备启停损耗、过渡时段重叠、实际执行偏差等。
### 10.4 基线能耗与实际节能计算（新增）
#### 10.4.1 基线能耗建立
基线能耗是计算实际节能效果的基准：
```
基线能耗 = 转移前 30 天的平均日能耗
基线费用 = 基线能耗 × 分时电价
```
**数据清洗**：
- 剥除异常值：超过 ±3σ 的数据点
- 剥除设备停机日：日能耗 < 10% 额定功率
- 剥除节假日：负载模式与平日差异较大
#### 10.4.2 实际节能计算
```
实际日节能 = 基线费用 - 转移后实际费用
达成率 = 实际日节能 / 预期日节能 × 100%
```
#### 10.4.3 不确定性分析
实际节能效果受多种因素影响，需要进行不确定性分析：
| 影响因素 | 不确定性范围 | 说明 |
|---------|------------|------|
| 天气变化 | ±10% | 温度变化影响制冷负载 |
| 负载波动 | ±15% | IT 负载波动影响总能耗 |
| 设备效率 | ±5% | 设备老化导致效率下降 |
| 执行偏差 | ±10% | 实际执行与计划的偏差 |
**综合不确定性**：
```
总不确定性 = √(σ₁² + σ₂² + σ₃² + σ₄²) ≈ ±21%
95% 置信区间 = [预期节能 × 0.79, 预期节能 × 1.21]
```

### 11.1 设备级约束

| 约束项 | 配置字段 | 说明 |

| 最低功率限制 | `min_power` | 设备运行的最低功率不可突破 |
| 最大转移时长 | `max_shift_duration` | 单次转移不可超过此时长 |
| 最小连续运行 | `min_continuous_runtime` | 设备启动后至少运行此时长 |
| 爬坡速率限制 | `max_ramp_rate` | 功率变化速度不可超过此值 (kW/min) |
| 禁止时段 | `forbidden_shift_hours` | 这些时段内不允许执行转移 |
| 允许时段 | `allowed_shift_hours` | 仅在这些时段内允许转移 |

### 11.2 算法级安全

| 安全机制 | 值 | 说明 |
|---------|-----|------|
| 安全系数 | ×0.85 | 推荐比例在四约束最小值基础上再打85折 |
| 额定功率校验 | >0 | 额定功率无效时直接返回推荐值0 |
| 范围校正 | 0~type_max | 推荐值强制限制在 [0, 设备类型上限] 范围内 |
| 变更阈值 | >1% | 差异低于1%不触发变更通知 |

### 11.4 电气安全约束（新增）
#### 11.4.1 三相平衡约束
负载转移必须考虑三相不平衡度，防止中性线过载：
| 约束项 | 阈值 | 说明 |
|--------|------|------|
| 最大不平衡度 | 15% | 根据 GB/T 15543-2008，三相不平衡度不应超过 15% |
| 中性线电流 | 相线的 50% | 中性线电流不应超过相线额定电流的 50% |
| 单相负载转移 | 优先转移重相 | 优先转移负载较重的相，减少不平衡 |
**计算公式**：
```
不平衡度 = max(|Ia-Iavg|, |Ib-Iavg|, |Ic-Iavg|) / Iavg × 100%
其中 Iavg = (Ia + Ib + Ic) / 3
```
#### 11.4.2 电能质量约束
| 指标 | 阈值 | 说明 |
|------|------|------|
| 总谐波电流率 (THDi) | < 5% | 根据 GB/T 14549-1993，防止谐波污染 |
| 功率因数 (PF) | > 0.9 | 保持高功率因数，减少无功损耗 |
| 电压波动 | ±7% | 符合 GB/T 12325-2008 电能质量标准 |
**监控机制**：
- 转移前检测当前 THDi 和 PF
- 转移后持续监控 5 分钟
- 超限时自动回退并告警
#### 11.4.3 设备启停约束
| 设备类型 | 预热时间 | 冷却时间 | 最小运行时间 | 说明 |
|---------|---------|---------|------------|------|
| 压缩机 | 5-10min | 5-10min | 30-60min | 防止频繁启停损坏压缩机 |
| 冷水机组 | 10-15min | 10-15min | 30-60min | 需要预热冷冻水系统 |
| HVAC | 10-15min | 5min | 15-30min | 预热防止冷凝，冷却防止过热 |
| 水泵 | 2-5min | 2-5min | 10-20min | 变频启动需要缓启动 |
### 11.5 算力中心特殊约束（新增）
#### 11.5.1 IT 负载占比约束
算力中心的 IT 负载通常占总能耗的 60-80%，且不可转移：
| 负载类型 | 占比 | 可转移性 | 说明 |
|---------|------|---------|------|
| IT 负载 | 60-80% | 不可转移 | 服务器、存储、网络设备 |
| 制冷系统 | 15-25% | 部分可转移 | 冷水机组、空调、冷却塔 |
| 配电系统 | 3-5% | 不可转移 | UPS、配电柜 |
| 照明及其他 | 2-5% | 可转移 | 照明、办公设备 |
**转移空间评估**：
```
最大可转移功率 = 总功率 × (制冷占比 × 0.4 + 其他占比 × 0.6)
例：1000kW 总功率，制冷 20%，其他 5%
最大可转移 = 1000 × (0.2 × 0.4 + 0.05 × 0.6) = 110kW
```
#### 11.5.2 UPS 容量约束
负载转移后的峰值功率不得超过 UPS 容量：
```
UPS 容量校验：
  转移后峰值功率 ≤ UPS 额定容量 × 0.8  // 留 20% 余量
  
如果超限：
  - 自动减少转移功率
  - 或者拒绝执行并告警
```
#### 11.5.3 制冷系统联动
负载转移会改变热负载分布，必须联动调整制冷系统：
| 场景 | 联动策略 | 说明 |
|------|---------|------|
| 峰时削减 IT 负载 | 同步降低冷水机组输出 | 减少制冷需求 |
| 谷时增加 IT 负载 | 提前 10-15min 启动冷水机组 | 预冷防止过热 |
| 负载快速变化 | 启用备用冷水机组 | 应对突发热负载 |
**实现机制**：
- 转移方案自动生成制冷调整任务
- 制冷系统先于 IT 负载 10-15min 执行
- 实时监控机房温度，超限自动回退
### 11.6 制冷与用电联动机制（新增 - 暖通工程师视角）
#### 11.6.1 制冷滞后效应与预测
机房温度变化有 15-30 分钟滞后，必须提前预测并调整制冷：
| IT 负载变化 | 机房温度响应时间 | 制冷调整措施 | 说明 |
|----------|--------------|------------|------|
| 增加 100kW | 15-20min | 提前 15min 增加制冷输出 | 防止温度超限 |
| 减少 100kW | 20-30min | 延迟 10min 降低制冷输出 | 利用热惯性节能 |
| 快速波动 | 10-15min | 维持当前制冷输出 | 避免频繁调整 |
**温度预测模型**：
```
T(t+Δt) = T(t) + (Q_IT - Q_cooling) / (m × C_p) × Δt
其中：
  T(t) = 当前机房温度
  Q_IT = IT 设备发热量 (kW)
  Q_cooling = 制冷系统移除热量 (kW)
  m = 机房空气质量 (kg)
  C_p = 空气比热容 (kJ/kg·K)
```
#### 11.6.2 冷量需求计算
IT 功率变化对应的制冷功率变化：
```
制冷功率变化 = IT 功率变化 / (PUE - 1)
例：IT 功率减少 100kW，PUE = 1.5
制冷功率减少 = 100 / (1.5 - 1) = 200kW
```
**冷吨转换**：
```
1 冷吨 (RT) = 3.517 kW
冷量需求 (RT) = 制冷功率 (kW) / 3.517
```
#### 11.6.3 制冷系统效率优化
冷水机组在不同负载下的效率不同：
| 负载率 | COP (制冷系数) | 能效比 | 说明 |
|------|-------------|--------|------|
| 100% | 3.5 | 100% | 额定负载 |
| 75% | 4.2 | 120% | **最佳运行点** |
| 50% | 3.8 | 109% | 部分负载 |
| 25% | 2.5 | 71% | 低效运行 |
**优化策略**：
- 尽量让冷水机组运行在 75% 负载附近
- 负载 < 50% 时，关闭部分机组，提高剩余机组负载率
- 负载 > 90% 时，启动备用机组，防止过载
#### 11.6.4 送风温度动态调节
根据 IT 负载调整送风温度，进一步节能：
| IT 负载率 | 送风温度 | 节能效果 | 说明 |
|----------|---------|---------|------|
| > 80% | 18℃ | 基准 | 高负载保证制冷 |
| 60-80% | 20℃ | 节能 5% | 正常负载 |
| 40-60% | 22℃ | 节能 10% | 中等负载 |
| < 40% | 24℃ | 节能 15% | 低负载最大节能 |
**注意事项**：
- 送风温度不应超过 27℃（ASHRAE 推荐上限）
- 温度调整速度不超过 2℃/h，防止冷凝
#### 11.6.5 PUE 优化路径分析
负载转移对 PUE 的影响路径：
```
PUE = 总能耗 / IT 能耗 = (IT 能耗 + 制冷能耗 + 其他) / IT 能耗
优化路径 1：降低峰时 IT 负载
  - IT 能耗降低 100kW
  - 制冷能耗降低 50kW（PUE=1.5）
  - PUE 从 1.50 降至 1.48（优化 1.3%）
优化路径 2：提高制冷系统效率
  - 冷水机组运行在 75% 负载（COP 提高 20%）
  - 制冷能耗降低 10kW
  - PUE 从 1.50 降至 1.48（优化 1.3%）
优化路径 3：提高送风温度
  - 送风温度从 18℃ 提高到 22℃
  - 制冷能耗降低 15kW（节能 10%）
  - PUE 从 1.50 降至 1.47（优化 2%）
**综合优化**：
同时应用三种路径，PUE 可降低 0.05-0.1（从 1.50 降至 1.40-1.45）
```

## 12. 执行与追踪

### 12.1 执行计划生命周期

```
 pending(待执行)
    │
    ▼  [点击"开始执行"]
 in_progress(执行中)
    │
    ├──▶ completed(已完成)   [所有任务完成]
    │
    └──▶ cancelled(已取消)   [手动取消]
```

### 12.2 任务类型

| 类型 | 说明 | 操作方式 |
|------|------|---------|
| `auto` | 自动任务 | 系统通过API发送调控指令，点击"执行"触发 |
| `manual` | 手动任务 | 需人工到现场操作设备，完成后点击"标记完成" |

### 12.3 效果追踪指标

| 指标 | 计算方式 |
|------|---------|
| 预期日节省 | 规划阶段计算的理论值 |
| 实际日节省 | 执行前后实际用电数据对比 |
| 达成率 | 实际节省 / 预期节省 × 100% |
| 预期年节省 | 预期日节省 × 250 |
| 实际年节省 | 实际日节省 × 250 |

### 12.4 配置回溯

执行计划的 `device_rules` 字段以 JSON 快照形式保存了创建时的完整规则配置。用户可以在执行管理页面点击"查看原配置"，跳转回分析页面并自动恢复当时的设备选择和规则配置。
### 12.5 失败回退与应急预案（新增）
#### 12.5.1 回退触发条件
| 触发条件 | 回退策略 | 说明 |
|---------|---------|------|
| UPS 负载超限 | 立即回退 | 负载 > UPS 容量 × 0.8 |
| 机房温度超限 | 5min 内回退 | 温度 > 28℃ |
| 三相不平衡超限 | 10min 内回退 | 不平衡度 > 15% |
| 电能质量超限 | 5min 内回退 | THDi > 5% 或 PF < 0.9 |
| 设备故障 | 立即回退 | 设备报警或离线 |
#### 12.5.2 回退执行流程
```
1. 检测到异常 → 触发回退信号
2. 暂停所有转移任务
3. 按原路径逆向恢复负载
   - 先恢复关键负载（IT 设备）
   - 再恢复非关键负载（制冷、照明）
4. 验证系统状态恢复正常
5. 记录回退原因和时间
6. 通知运维人员
```
#### 12.5.3 应急预案
| 场景 | 应急措施 | 责任人 |
|------|---------|---------|
| 转移失败 | 手动回退 + 检查设备 | 电气工程师 |
| 设备故障 | 启用备用设备 | 运维人员 |
| 系统崩溃 | 切换到手动模式 | 系统管理员 |
| 电网故障 | 启用 UPS + 发电机 | 电气工程师 |
### 12.6 运营 KPI 指标体系（新增 - 运营总监视角）
#### 12.6.1 核心 KPI 指标
| 指标类别 | 指标名称 | 计算公式 | 目标值 | 说明 |
|---------|---------|---------|--------|------|
| 执行效率 | 执行成功率 | 成功任务数 / 总任务数 | > 95% | 衡量系统可靠性 |
| 执行效率 | 平均响应时间 | 从触发到完成的平均时间 | < 15min | 衡量执行效率 |
| 执行效率 | 回退率 | 回退任务数 / 总任务数 | < 5% | 衡量方案质量 |
| 经济效益 | 节能达成率 | 实际节能 / 预期节能 | > 80% | 衡量经济效果 |
| 经济效益 | ROI | (年节省 - 年成本) / 初始投资 | > 15% | 衡量投资回报 |
| 安全性 | 故障率 | 故障次数 / 总执行次数 | < 1% | 衡量系统安全 |
| 安全性 | 业务影响时间 | 因负载转移导致的业务中断时间 | 0 | 业务连续性 |
| 设备健康 | 设备故障增量 | 转移后故障率 - 转移前故障率 | < 10% | 衡量设备损耗 |
#### 12.6.2 分时段运营策略
| 时段类型 | 转移策略 | 执行频率 | 说明 |
|---------|---------|---------|------|
| 工作日峰时 | 积极转移 | 每日 2-3 次 | 电价差最大，收益最高 |
| 工作日谷时 | 适度转移 | 每日 1-2 次 | 利用低价时段 |
| 周末 | 保守转移 | 每日 0-1 次 | 负载低，转移空间小 |
| 节假日 | 暂停转移 | 0 | 设备休息，减少损耗 |
| 夏季（6-9月） | 增强转移 | 每日 3-4 次 | 制冷负载高，节能潜力大 |
| 冬季（12-2月） | 减少转移 | 每日 1-2 次 | 制冷负载低，节能潜力小 |
#### 12.6.3 人员配置与技能要求
| 角色 | 人数 | 技能要求 | 职责 |
|------|------|---------|------|
| 系统管理员 | 1 | 系统配置、故障排查 | 系统维护、方案优化 |

#### 12.6.4 业务影响评估模型
量化负载转移对业务的影响：
| 影响类型 | 衡量指标 | 可接受阈值 | 说明 |
|---------|---------|----------|------|

| 可用性 | 服务中断时间 | 0 | 不允许业务中断 |
| 数据一致性 | 数据丢失率 | 0 | 不允许数据丢失 |
**监控机制**：
- 转移前：基线性能测试（API 响应时间、并发数）
- 转移中：实时监控业务指标
- 转移后：对比分析，评估影响
- 超限自动回退：响应时间增加 > 20% 或并发数降低 > 30%

### E. 投资回报分析模型（新增）

#### E.2 收益计算

```

例：日节省 1250 元 → 年节省 31.25 万元
```
**间接收益**：
- 需量优化：降低最大需量，减少基本电费 5-10%
- PUE 优化：制冷系统优化，降低 PUE 0.05-0.1

### F. 设备寿命与维护管理（新增 - 设备维护工程师视角）
#### F.1 设备寿命损耗模型
频繁启停对设备寿命的影响：
| 设备类型 | 正常寿命 | 每次启停损耗 | 年转移次数 | 寿命减少 | 说明 |
|---------|---------|------------|----------|---------|------|
| 压缩机 | 10 年 | 0.5 天 | 500 次 | **250 天 (6.8%)** | 启停冲击大 |
| 冷水机组 | 15 年 | 0.3 天 | 500 次 | **150 天 (2.7%)** | 热冲击损耗 |
| 水泵 | 8 年 | 0.2 天 | 500 次 | **100 天 (3.4%)** | 轴承磨损 |
| HVAC | 12 年 | 0.3 天 | 500 次 | **150 天 (3.4%)** | 电机启停损耗 |
| 照明 | 5 年 | 0.1 天 | 500 次 | **50 天 (2.7%)** | 灯管寿命影响小 |
**寿命损耗计算公式**：
```
寿命减少 (天) = 每次启停损耗 (天) × 年转移次数
寿命减少比例 = 寿命减少 (天) / 正常寿命 (天)
```
#### F.2 维护周期调整策略
负载转移后，设备维护周期需要调整：
| 设备类型 | 原维护周期 | 调整后周期 | 调整原因 |
|---------|----------|----------|---------|
| 压缩机 | 6 个月 | **4 个月** | 启停次数增加，需提前检查 |
| 冷水机组 | 12 个月 | **9 个月** | 运行模式变化，增加检查 |
| 水泵 | 6 个月 | **4 个月** | 轴承磨损加快 |
| HVAC | 12 个月 | **9 个月** | 滤网清洗频率增加 |
| 照明 | 24 个月 | **24 个月** | 影响较小，不调整 |
**维护成本增加**：
```
年维护成本增加 = Σ (设备数量 × 单次维护成本 × 额外维护次数)
估计增加 3-5 万元/年
```
#### F.3 故障率预测模型
基于威布尔分布预测设备故障率：
```
故障率 = 1 - exp[-(t/η)^β]
其中：
  t = 运行时间
  η = 特征寿命（受转移影响）
  β = 形状参数（设备特性）
```
**故障率增加预测**：
| 设备类型 | 原故障率 | 转移后故障率 | 增加比例 | 说明 |
|---------|---------|------------|---------|------|
| 压缩机 | 2%/年 | **2.5%/年** | +25% | 高风险设备 |
| 冷水机组 | 1.5%/年 | **1.8%/年** | +20% | 中等风险 |
| 水泵 | 3%/年 | **3.6%/年** | +20% | 中等风险 |
| HVAC | 2%/年 | **2.3%/年** | +15% | 低风险 |
| 照明 | 1%/年 | **1.1%/年** | +10% | 最低风险 |
#### F.4 备件库存优化
根据故障率增加调整备件库存：
| 备件类型 | 原库存量 | 调整后库存 | 增加成本 | 说明 |
|---------|---------|----------|---------|------|
| 压缩机关键零件 | 1 套 | **2 套** | 5 万元 | 高故障率设备 |
| 冷水机组零件 | 1 套 | **1 套** | 0 | 保持不变 |
| 水泵轴承 | 2 个 | **3 个** | 0.5 万元 | 易损件 |
| HVAC 滤网 | 10 个 | **15 个** | 0.3 万元 | 消耗品 |
| **总计** | - | - | **5.8 万元** | 一次性投入 |
#### F.5 设备健康监测指标
实时监测设备健康状态，预防性维护：
| 监测指标 | 正常范围 | 预警阈值 | 告警阈值 | 处理措施 |
|---------|---------|---------|---------|---------|
| 压缩机振动 | < 5mm/s | 5-10mm/s | > 10mm/s | 停机检修 |
| 轴承温度 | < 60℃ | 60-80℃ | > 80℃ | 更换轴承 |
| 电机电流 | 80-100% | 100-110% | > 110% | 降低负载 |
| 冷媒压力 | 0.8-1.2MPa | 1.2-1.5MPa | > 1.5MPa | 检查泄漏 |
| 水泵流量 | 90-110% | 80-90% | < 80% | 清洗管道 |
**监测频率**：
- 实时监测：每 5 秒采集一次
- 趋势分析：每天生成健康报告

#### E.5 需量电费优化计算（新增）
中国大部分地区采用“两部制电价”：
```
总电费 = 基本电费 + 电度电费
基本电费 = 最大需量 (kW) × 基本电价 (元/kW·月)
电度电费 = 用电量 (kWh) × 分时电价 (元/kWh)
```
**需量优化效果**：
| 场景 | 原最大需量 | 优化后需量 | 需量降低 | 基本电费节省 |
|------|-----------|-----------|--------|------------|
| 小型机房 | 500kW | 450kW | 10% | 50kW × 30元/kW·月 × 12月 = **1.8万元/年** |
| 中型机房 | 2000kW | 1800kW | 10% | 200kW × 30元/kW·月 × 12月 = **7.2万元/年** |
| 大型机房 | 5000kW | 4500kW | 10% | 500kW × 30元/kW·月 × 12月 = **18万元/年** |
#### E.6 季节性节能分析（新增）
不同季节的节能潜力差异很大：
| 季节 | PUE | 制冷负载占比 | 节能潜力 | 说明 |
|------|-----|-----------|---------|------|
| 夏季 (6-9月) | 1.6-1.8 | 35-40% | **最高** | 制冷负载高，节能空间大 |
| 春秋 (3-5, 10-11月) | 1.4-1.5 | 20-25% | 中等 | 温度适中，制冷需求中等 |
| 冬季 (12-2月) | 1.3-1.4 | 10-15% | **最低** | 制冷负载低，节能空间小 |
**季节性策略**：
- 夏季：增加转移频率，每日 3-4 次
- 春秋：正常转移，每日 2-3 次
- 冬季：减少转移，每日 1-2 次，以减少设备损耗
#### E.7 碳排放效益计算（新增）
负载转移带来的碳减排效益：
```
碳排放减少 (tCO₂) = 节省电量 (kWh) × 电网碳排放因子 (kgCO₂/kWh)
中国电网平均碳排放因子 ≈ 0.6 kgCO₂/kWh
例：年节省 50 万 kWh
碳排放减少 = 500,000 × 0.6 = 300 tCO₂
```
**碳交易收益**（适用于有碳交易市场的地区）：
```
碳交易收益 = 碳排放减少 (tCO₂) × 碳价 (元/tCO₂)
当前中国碳价 ≈ 60-80 元/tCO₂
例：300 tCO₂ × 70 元/tCO₂ = 2.1 万元/年
```
#### E.8 修正后的投资回报分析（NPV & IRR）
**净现值 (NPV) 计算**：
```
NPV = -初始投资 + Σ [年净收益 / (1 + 折现率)^t]
折现率取 8%（企业加权平均资本成本 WACC）
```
**内部收益率 (IRR)**：
```
IRR = 使 NPV = 0 的折现率
```
**修正后的投资回报表**：
| 场景 | 初始投资 | 年总收益 | 年总成本 | 年净收益 | 简单回报期 | NPV (10年) | IRR |
|------|---------|---------|---------|---------|----------|----------|-----|
| 小型机房 | 75万 | 22万 | 41万 | -19万 | **负收益** | -200万 | - |
| 中型机房 | 100万 | 42万 | 56万 | -14万 | **负收益** | -180万 | - |
| 大型机房 | 160万 | 78万 | 71万 | 7万 | **22.9年** | -110万 | 2.5% |
**重要结论**：
- 考虑隐性成本后，小中型机房为负收益，**不建议实施**
- 大型机房回报期达 23 年，IRR 仅 2.5%，**经济性较差**
- 建议仅在以下情况下实施：
  - 电价差 > 1.5 元/kWh（尖谷差）
  - 年运行天数 > 300 天（非 250 工作日）
  - 有政府补贴或碳交易收益

#### G.3 算法简化方案（MVP）
**简化的四约束模型**：
```python
# MVP 版本：仅考虑约束 1 和约束 4
def calculate_recommendation_mvp(device):
    # 约束 1：最低功率约束
    constraint_1 = max(0, 1 - device.min_power / device.rated_power)
    
    # 约束 4：设备类型硬上限
    constraint_4 = TYPE_MAX_RATIOS.get(device.type, 0.3)
    
    # 取最小值 + 安全系数
    raw_ratio = min(constraint_1, constraint_4)
    return round(raw_ratio * 0.85, 2)
```
